## 빠른 검색 초안으로 전환 · 2026-11-03

사용자 정정으로 전체 대화 페이지 순회·구간별 누적 요약·재귀 분할을 문서 생성에서 제거했다. 기존 messages search API로 질문에서 추출한 최대6개 핵심 단어를 첫40개씩 제한 조회한다(동시3개). 단일 발언자는 DB 조건에도 적용하고 복수 발언자는 후보에서 제한한다. 중복·무관·제외 화자를 제거하고 관련도순 최대16개/약6KB의 단어 주변 발췌만 한 번에 Qwen에 보낸다. 조회한 후보가 없으면 대화 없이 질문만 정리한다. 전체 데이터에서 일치가 전혀 없음을 보장하는 검색은 아니며 first-page 제한과 복수 화자 희소 조건으로 관련 발언을 놓칠 수 있다. 결과에 검색어·후보 수·참고 수·부분 조사 경고를 표시한다.

AI 호출은 기본1회, 실패 시 입력을 줄여 최대1회 재시도하며 previous=null이다. 재귀 분할·누적/전체 요약은 없다. 모델 단계는60초 대기 제한, 출력1536토큰·짧은 초안 지시를 사용한다. DB 검색 시간은 별도이며 완료 시간을 보장하지 않는다. JEV 관련성 호출은 추가하지 않아 대기 경로를 늘리지 않는다. 기존 인용 검증·주제별 응답 기준·원문 제외 의견 입력은 유지한다. sourceCoverage JSON에 mode=keyword/keywords/matchedMessages/searchFailed를 추가하며 신규 DB 마이그레이션은 없다. 순수 검색/발췌 함수를 document-search.ts로 분리하고 기존 Adapter/DI를 유지했다.

이전의 ‘모든 페이지 조사/구간별 복구’ 문서 기록은 과거 동작이다. 사용자 직접 시험을 위해 실제 AI 요청·학교 서버 변경은 하지 않았다. 새 문서 생성 요청부터 적용한다.


## 문서 근거 품질 보완 · 2026-11-03

사용자 요청으로 문서 품질만 보완했다. **실제 학교 AI 요청·모델 실험·서버 재시작은 실행하지 않고 사용자 직접 시험을 기다린다.** 프롬프트는 질문 의도·사실/참여자 의견/가정/미확인 정보·쟁점·판단 기준을 분리하고 없는 반대 논거나 합의를 채우지 않도록 강화했다. optional factEvidence(최대8개: text/kind/messageId/quote)를 생성하며 reported/opinion의 인용은 실제 현재 구간에 포함되거나 이전 구간에서 확인한 동일 항목이어야 한다. 위조 ID/인용·이전 사실 변형은 AI_TOPIC_EVIDENCE로 거절하고 기존 재시도/분할 정책을 따른다. 가정·미확인 항목에는 원문 근거를 붙이지 않는다.

화면은 항목별 분류·원문 인용·근거 이동 버튼을 표시한다. facts는 분류 문구를 포함해 의견 모델에 전달하지만 원문 인용과 ID는 기존 opinionContext 허용 목록으로 제외한다. 사용자 facts 변경은 오래된 factEvidence를 지워 잘못된 근거 연결을 방지한다. 근거 연결 없는 과거 문서는 확인 경고와 함께 호환한다. document JSON 확장이며 새 DB 컬럼·원격 SQL·런타임 의존성은 없다. 기존 Adapter/DI를 유지하고 document-grounding.ts의 순수 함수로 검증 책임을 분리했다.

이 검증은 **인용 존재와 출처 연결 확인**이다. 발언의 진위·법률 현행 여부·요약의 의미적 타당성을 자동 보장하지 않는다. 외부 조사 기능을 추가하지 않았으며 관련 자료가 없으면 미확인으로 남긴다. 변경 후 생성되는 새 문서에 적용되고 과거 저장 문서를 자동 재생성하지 않는다.


## 주제별 판단 문서·응답 구현 · 2026-11-03

사용자 후속 실행 요청으로 계획의 구현에 착수했다. 문서는 질문 의도→관련 사실/주장/미확인 정보→쟁점→판단 기준→응답 유형과 선택지를 생성한다. `answerSchema`는 stance/numeric/choice이며 금액에 고정하지 않는다. facts와 응답 기준은 편집 가능하고 원문은 사실 확인용으로 제공한다. 원문 체크만으로 입력이 달라지는 것처럼 보이던 UI를 제거했다. 선택지는2~9개, 수치형은 연속 하한 포함/상한 제외 구간과 별도 보류 항목을 검증한다. Qwen은 상세 결론·수치(수치형만)·근거 특성, JEV v2는 같은 문서의 항목 ID·조건부 확률을 반환한다. JEV 구간을 정확한 금액으로 변환하지 않고 수치 평균은 상세 실제 응답만 사용한다.

공통 인터페이스/DI·HTTP Adapter를 유지하고 검증은 answer-schema.ts의 순수 함수로 분리했다. 과거 문서는 v1 찬반 호환 경로로 읽는다. 새 결과는 고정 동의도/신뢰도 스펙트럼을 주요 결과로 사용하지 않으며 이름 옆에 실제 수치/선택 결과를 표시한다. 연령대·성별·지역·학력 그래프는 바로 보이고 나머지7개는 개별 펼침 영역, 분석에 사용한 추가 조건은 기본 펼침이다. 기존20+180 예산과 AI 진행 표시를 유지한다. 새 런타임 의존성·파일 이동/삭제·커밋/푸시·DB 마이그레이션은 없다.

SSH 직접 접속(-F NUL)으로 기존 설치를 확인했고, 꺼져 있던 Qwen/JEV를 기존 캐시로 재기동했다. JEV 브리지를 v1/v2 호환으로 반영하고 로컬18080/18081 터널을 열었다. 상세 술 정산 합성 사례에서 금액형 문서·상세 답변·JEV 구간 응답을 확인했다. 실제 모델 실험은 소규모이며 품질 전반 개선이나200명 전체 성공을 뜻하지 않는다. 백엔드106개 테스트·JEV4개 테스트 및 프론트 타입/lint, 백엔드 빌드/lint 통과 기록이 있다. 최종 주제3종 분류 검증과 화면 시각 검증 상태는 별도 결과를 따른다.

수동 확인: 로그인 → 카카오톡 TXT 선택 → 제목 확인 → 대화 저장 → 원문/통계 조회 → 새로고침 후 유지 → 기간·참여자·검색 변경 → 삭제 확인 후 원본/DB 제거를 확인한다. 동일 이름 참여자는 구분할 수 없으며 첨부 실제 파일과 응답 시간은 분석하지 않는다. 파싱 오류는 원본이 아닌 안내 문구로 표시한다.

자동 타입·lint·빌드, 백엔드 20개 테스트, 원격 DB 롤백 SQL은 통과했다. 브라우저 목록·업로드 화면은 확인했지만 Chrome 확장 파일 URL 접근이 꺼져 파일 선택 및 populated 원문·통계 전체 UI 검증은 미실행이다. 지속적 테스트 Auth 계정 생성은 자동 승인 검토에서 거절되었으며 계정 생성 없이 롤백 검증만 수행했다.

브랜치: codex/m2/frontend-screens. 기반: codex/m0/environment-setup. Next.js 16.3.8 App Router, React 19, Tailwind 4, shadcn Button을 사용한다. 기존 디자인 인계는 [design.md](design.md)를 따른다.

## 범위와 제한

- OAuth 로그인·사용자 프로필 API 연결 코드는 구현했으며 실로그인 검증은 사용자 수행 예정이다. 대화 개인 저장·서버 파싱·AI 호출·외부 캘린더는 미연결이다. 앱 자체 비밀번호 폼은 제공하지 않는다.
- 예시 변경은 탭 메모리에만 남으며 새로고침 시 초기화한다. 삭제는 서버 데이터를 변경하지 않는다.
- 실제 파일은 브라우저에서만 읽고 앞 4,000자를 표시한다. 로컬 미리보기 보호 한도 2MB는 서버 업로드 정책이 아니다. 선택한 실제 파일을 합성 결과로 파싱한 것처럼 보여주지 않는다.
- 평균 응답 시간은 집계 계약 미확정이므로 계산값을 꾸며내지 않고 준비 중으로 표시한다. Figma의 큰 통계 예시 숫자를 대신해 표시한 5개·2개 메시지를 실제 집계한다.
- 분석 대기·처리·완료·실패는 타이머 기반 체험이고 결과는 사전 작성 합성 예시다. 화면 이탈 시 타이머를 정리한다.
- 일정 저장은 ID 기준 교체로 중복 저장을 막으며 시간 미정 후보는 필수 입력 후 저장한다.
- Vite 패키지는 제거했다. 기존 main.tsx·index.html·비활성 vite.config.ts는 실행하지 않는 이전 진입점 기록으로 남겼다. 운영은 정적 Nginx 빌드 대신 Next.js Node 런타임을 필요로 한다.

## OAuth 로그인 연결 · 2026-10-03

브랜치 `codex/m2/oauth-login`. 기존 화면 체험용 이메일·비밀번호 폼을 공식 리소스를 사용하는 세 제공자 버튼으로 교체했다. 로그인 시작은 Supabase OAuth, 콜백은 PKCE 세션 교환 후 GET /api/users/me 확인, 성공하면 대화 화면으로 이동한다. 상단 계정 링크에서 /login의 내 계정 화면을 열어 닉네임 수정과 현재 세션 로그아웃을 수행한다.

| 흐름 | 처리 |
| --- | --- |
| 로그인 시작 | provider=google/github/kakao, 현재 브라우저 origin + /auth/callback으로 redirectTo 지정 |
| 콜백 | 인가 코드 한 번 교환·브라우저 세션 저장·내 정보 조회 후 /conversations 이동 |
| 서버 장애 | 콜백 오류 안내·다시 확인 버튼; 이미 성공한 코드 교환은 반복하지 않음 |
| 닉네임 | 앞뒤 공백 제거, Unicode 1~30자 입력, PATCH /api/users/me 후 갱신 |
| 세션 | SDK 복원·자동 갱신, API 401 시 현재 세션 정리·재로그인 안내 |
| 화면 체험 | 로그인 없이 접근 유지, 대화 화면은 합성 데이터라고 계속 표시 |

### 사용자 확인 절차

1. 루트 .env의 Supabase URL·publishable 키, Dashboard의 Google·GitHub·Kakao 활성화를 확인한다.
2. Supabase Site URL은 http://localhost:5173, Redirect URLs는 http://localhost:5173/auth/callback으로 설정한다. 제공자 앱 콜백은 프로젝트의 https://fthzjaeucyiudbjxmlgu.supabase.co/auth/v1/callback이다.
3. dev 서버를 재시작하고 `pnpm dev`로 프론트·백엔드를 함께 실행한 뒤 http://localhost:5173/login을 연다. localhost와 127.0.0.1을 혼용하지 않는다.
4. 제공자 버튼 → 제공자 로그인/동의 → 콜백 → 대화 화면 이동과 상단 내 계정 표시를 확인한다. Supabase profiles에 본인 행이 생성됐는지도 확인한다.
5. 상단 내 계정에서 닉네임 저장·새로고침 후 유지·로그아웃·다시 로그인 흐름을 확인한다.

요청에 따라 에이전트는 타입 검사·lint·빌드·브라우저·로그인·API·컨테이너 테스트를 실행하지 않았다. 실제 로그인 완료를 검증한 상태가 아니며 사용자가 실행 후 오류를 알려줄 예정이다. 최초 제공자 로그인 시 Auth 사용자와 profiles 행이 실제로 생성된다. 현재 로그인은 대화 저장·AI 연결 완료를 의미하지 않는다.

## 일정 입력 개선 · 2026-10-03

일정은 기존 shadcn Calendar/Popover DatePicker와 Select 기반 재사용 TimePicker로 날짜·시·분을 입력한다. 선택적 종료 시각을 제공하며 카드에 날짜·시작~종료, 근거 메시지 발언 시점, 제안 확인 경고를 표시한다. 후보는 서버 suggestion으로 초기화하고 확정 일정은 저장된 값으로 초기화한다. 날짜·시각 필수값 및 같은 날 종료 순서를 검증한다. 달력은 미래 연도도 선택할 수 있다.

## 페르소나 논쟁 화면 · 2026-11-02

`opinions` 경로는 논쟁 입력 옆에 페르소나/발언자 선택·표본 미리보기 사이드바를 상시 표시한다. 내부는 가로 카드·선택 버튼이며 열기/닫기 팝오버가 없다. 좁은 화면에서는 입력 아래로 이어진다. 항목별 전체 선택과 개별 선택은 배타적이다. 별도 `/opinions/:analysisId`에서 문서 작성·수정·저장·확정 후 결과 표시, 진행 중2초 폴링·오류 재조회를 제공한다. `/opinions/history`에서20개씩 기록을 조회한다. 계정·대화·분석별 컴포넌트를 다시 만들어 이전 결과를 혼합하지 않는다.

| 영역 | 동작 |
| --- | --- |
| 전체 분포 | 완료 응답만 원형 차트와 수/비율 표에 표시, 실패 수 별도 |
