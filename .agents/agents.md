POST /api/persona-debates/:id/restart {mode:'document'|'opinions'} →202. 본인 failed 작업만 허용하며 원래 실패 기록은 보존한다. 입력·필터·발언자를 복사한 새 UUID/새 표본 작업을 만든다. document는 빠른 문서 생성 후review에서 멈추고, opinions는 저장된 문서 스냅샷을 복사해 의견을 새로 요청한다(이전 부분 응답 이어받기는 아님). 문서 없음400·잘못된 모드400·타인404·실패 이외409·활성 작업 제한과 DB 중복 방지를 유지한다. 기존 인터페이스/DI·저장소 Adapter를 재사용해 DB 마이그레이션·권한 변경은 없다.

실패 카드에 문서 생성 다시시작 또는 AI 의견 요청 다시시작을 제공하고 문서가 있으면 문서부터 다시 만들기도 옆에 표시한다. 접수 중 비활성화·진행 표시·오류 안내·새 분석 페이지 이동을 연결했다. 자동 재요청하지 않고 사용자의 버튼 클릭으로만 실행한다.


## 빠른 검색 초안으로 전환 · 2026-11-03

검증: 백엔드111개 테스트·빌드·lint, 프론트 타입·lint 통과. 생성된 개발용 Next 타입 파일의 중복 꼬리를 정상 typegen 결과로 복구했다. 실제 AI 요청/성능 측정·브라우저 시각 검증은 미실행이며 기존 진행 작업을 새 방식으로 자동 전환하지 않는다.

사용자 정정으로 전체 대화 페이지 순회·구간별 누적 요약·재귀 분할을 문서 생성에서 제거했다. 기존 messages search API로 질문에서 추출한 최대6개 핵심 단어를 첫40개씩 제한 조회한다(동시3개). 단일 발언자는 DB 조건에도 적용하고 복수 발언자는 후보에서 제한한다. 중복·무관·제외 화자를 제거하고 관련도순 최대16개/약6KB의 단어 주변 발췌만 한 번에 Qwen에 보낸다. 조회한 후보가 없으면 대화 없이 질문만 정리한다. 전체 데이터에서 일치가 전혀 없음을 보장하는 검색은 아니며 first-page 제한과 복수 화자 희소 조건으로 관련 발언을 놓칠 수 있다. 결과에 검색어·후보 수·참고 수·부분 조사 경고를 표시한다.

AI 호출은 기본1회, 실패 시 입력을 줄여 최대1회 재시도하며 previous=null이다. 재귀 분할·누적/전체 요약은 없다. 모델 단계는60초 대기 제한, 출력1536토큰·짧은 초안 지시를 사용한다. DB 검색 시간은 별도이며 완료 시간을 보장하지 않는다. JEV 관련성 호출은 추가하지 않아 대기 경로를 늘리지 않는다. 기존 인용 검증·주제별 응답 기준·원문 제외 의견 입력은 유지한다. sourceCoverage JSON에 mode=keyword/keywords/matchedMessages/searchFailed를 추가하며 신규 DB 마이그레이션은 없다. 순수 검색/발췌 함수를 document-search.ts로 분리하고 기존 Adapter/DI를 유지했다.

이전의 ‘모든 페이지 조사/구간별 복구’ 문서 기록은 과거 동작이다. 사용자 직접 시험을 위해 실제 AI 요청·학교 서버 변경은 하지 않았다. 새 문서 생성 요청부터 적용한다.


## 문서 근거 품질 보완 · 2026-11-03

사용자 요청으로 문서 품질만 보완했다. **실제 학교 AI 요청·모델 실험·서버 재시작은 실행하지 않고 사용자 직접 시험을 기다린다.** 프롬프트는 질문 의도·사실/참여자 의견/가정/미확인 정보·쟁점·판단 기준을 분리하고 없는 반대 논거나 합의를 채우지 않도록 강화했다. optional factEvidence(최대8개: text/kind/messageId/quote)를 생성하며 reported/opinion의 인용은 실제 현재 구간에 포함되거나 이전 구간에서 확인한 동일 항목이어야 한다. 위조 ID/인용·이전 사실 변형은 AI_TOPIC_EVIDENCE로 거절하고 기존 재시도/분할 정책을 따른다. 가정·미확인 항목에는 원문 근거를 붙이지 않는다.

화면은 항목별 분류·원문 인용·근거 이동 버튼을 표시한다. facts는 분류 문구를 포함해 의견 모델에 전달하지만 원문 인용과 ID는 기존 opinionContext 허용 목록으로 제외한다. 사용자 facts 변경은 오래된 factEvidence를 지워 잘못된 근거 연결을 방지한다. 근거 연결 없는 과거 문서는 확인 경고와 함께 호환한다. document JSON 확장이며 새 DB 컬럼·원격 SQL·런타임 의존성은 없다. 기존 Adapter/DI를 유지하고 document-grounding.ts의 순수 함수로 검증 책임을 분리했다.

이 검증은 **인용 존재와 출처 연결 확인**이다. 발언의 진위·법률 현행 여부·요약의 의미적 타당성을 자동 보장하지 않는다. 외부 조사 기능을 추가하지 않았으며 관련 자료가 없으면 미확인으로 남긴다. 변경 후 생성되는 새 문서에 적용되고 과거 저장 문서를 자동 재생성하지 않는다.


### 문서 품질 검증에서 발견한 실패와 제한

위 주제3종의 유형 구분은 맞았지만 입력 대화가 없는 실험에서 Qwen이 확인되지 않은 법률 내용을 ‘확인됨’으로, 존재하지 않는 참여자의 주장을 사실 목록으로 생성했다. 따라서 이 실험은 문서 정확성 통과가 아니다. 관련 대화/이전 문서가 전혀 없는 경우에는 서버가 질문만 보존하고 요약·사실·쟁점을 ‘근거 없음/미확인’으로 제한하며 임의 논거를 제거하는 방어를 추가했다. 찬반 선택지도 중립적인 동의/반대/보류 기준으로 제한한다. 대화가 있는 경우까지 개별 사실과 출처를 자동 검증하는 구조는 미완료다. 이 점과 JEV의 오답 때문에 전반적 성능 개선 완료로 보고하지 않는다. 프론트 호스트 빌드는 통과했다.


### 실제 주제별 문서 검증 결과

학교 Qwen에서 ‘청년적금 월 지원액’→numeric, ‘민식이법은 악법인가’→stance, ‘현금 지급/교통 이용권’→choice를 각각 확인했다. 보고서는 Git 제외 `.tmp/gpu-ai/topic-kinds-report.json`. 법률 사실을 외부 검증한 실험이 아니라 질문별 문서 구조/응답 유형 검증이다. 수치 구간 라벨은 모델 문구의 이하/미만 오류를 방지하도록 서버가 경계값으로 생성한다.

중요한 한계: 술 정산 합성 사례의 상세 Qwen은60,000/3=20,000원을 답했으나 JEV0.6B는1만원 미만 구간을 선택했다(조건부 확률 약0.795). **구조 연결은 성공했지만 정답 품질 검증에는 실패했다.** 수치를 높이거나 정답처럼 숨기지 않는다. 단순 계산도 JEV가 틀릴 수 있으므로 프롬프트 개선만으로 품질이 해결됐다고 보고할 수 없다. 선택지 순서 대조·더 강한 모델 비교·객관식 계산 검증이 후속 과제다. 전체200명 품질 실험·최종 화면 시각 검증은 미실행이다. 원문 근거는 사실 확인용, 편집한 facts는 모델에 전달되지만 개별 사실별 source ID 연결과 품목별 전용 표 편집은 아직 없다.


## 주제별 판단 문서·응답 구현 · 2026-11-03

사용자 후속 실행 요청으로 계획의 구현에 착수했다. 문서는 질문 의도→관련 사실/주장/미확인 정보→쟁점→판단 기준→응답 유형과 선택지를 생성한다. `answerSchema`는 stance/numeric/choice이며 금액에 고정하지 않는다. facts와 응답 기준은 편집 가능하고 원문은 사실 확인용으로 제공한다. 원문 체크만으로 입력이 달라지는 것처럼 보이던 UI를 제거했다. 선택지는2~9개, 수치형은 연속 하한 포함/상한 제외 구간과 별도 보류 항목을 검증한다. Qwen은 상세 결론·수치(수치형만)·근거 특성, JEV v2는 같은 문서의 항목 ID·조건부 확률을 반환한다. JEV 구간을 정확한 금액으로 변환하지 않고 수치 평균은 상세 실제 응답만 사용한다.

공통 인터페이스/DI·HTTP Adapter를 유지하고 검증은 answer-schema.ts의 순수 함수로 분리했다. 과거 문서는 v1 찬반 호환 경로로 읽는다. 새 결과는 고정 동의도/신뢰도 스펙트럼을 주요 결과로 사용하지 않으며 이름 옆에 실제 수치/선택 결과를 표시한다. 연령대·성별·지역·학력 그래프는 바로 보이고 나머지7개는 개별 펼침 영역, 분석에 사용한 추가 조건은 기본 펼침이다. 기존20+180 예산과 AI 진행 표시를 유지한다. 새 런타임 의존성·파일 이동/삭제·커밋/푸시·DB 마이그레이션은 없다.

SSH 직접 접속(-F NUL)으로 기존 설치를 확인했고, 꺼져 있던 Qwen/JEV를 기존 캐시로 재기동했다. JEV 브리지를 v1/v2 호환으로 반영하고 로컬18080/18081 터널을 열었다. 상세 술 정산 합성 사례에서 금액형 문서·상세 답변·JEV 구간 응답을 확인했다. 실제 모델 실험은 소규모이며 품질 전반 개선이나200명 전체 성공을 뜻하지 않는다. 백엔드106개 테스트·JEV4개 테스트 및 프론트 타입/lint, 백엔드 빌드/lint 통과 기록이 있다. 최종 주제3종 분류 검증과 화면 시각 검증 상태는 별도 결과를 따른다.

## 공통 행동 규칙

- 모든 문서와 답변은 특별한 지시가 없으면 한국어로 작성한다. 핵심을 먼저 간결히 설명한다. 비교·변경·구조화된 데이터는 표로 정리한다.
- 명시적 사용자 지시와 상위 지침을 우선한다. 파일·폴더 이동과 삭제는 특별한 요청 없이 수행하지 않는다. 새 구조는 근거를 설명한다.
- SOLID와 책임 분리를 따른다. 기능 계약에는 인터페이스를 우선하고, 공통 상태·구현과 IS-A 관계가 명확할 때 추상 클래스를 선택한다.
- 새 클래스 전 유사 속성·기능과 책임 과다 여부를 확인한다. 클래스명은 최대 30자로 간결하게 정한다.
- 필요한 디자인 패턴만 적용하고 목적을 결과 보고에 설명한다. 단순 생성에 빌더·팩토리를 추가하거나 편의를 위해 싱글톤을 도입하지 않는다.
- 기술의 사용법·설정·버전을 조사할 때 작업 분야 문서의 공식 링크에서 해당 주제를 먼저 확인한다(frontend: Next.js, backend: NestJS, database: Supabase, infra: AWS). 공식 문서 내용이 부족하면 Context7 MCP로 보완하고 공식 저장소·릴리스 등 1차 출처를 확인한다. 다른 기술은 해당 기술의 공식 문서를 사용한다. 일반 개념·논문·실제 오류 사례·최신 발표는 인터넷의 1차 출처로 조사한다.
- 외부 검색은 영어를 기본으로 하되 한국 자료는 한국어로 찾는다. MCP 오류·반려는 동일 작업에서 최초 시도 포함 최대 3회까지만 시도하고 실패를 보고한다.
- 코드 작성 후 변경에 적합한 검증을 실행한다. 오류 수정·재검증은 최대 3회 수행하며 해결되지 않으면 실패와 남은 문제를 보고한다. 실패를 숨기거나 완료로 표시하지 않는다.
- 비밀 키·토큰·원본 개인 대화는 문서·저장소·로그에 기록하지 않는다. 예시는 합성 데이터를 사용한다.
- 선택된 설계, 구현 완료, 보류를 구분한다. 설치 버전·주소·인스턴스·명령을 추측하여 기록하지 않는다.

## 문서 중심 분석 흐름 개선 · 2026-11-02

입력 탭은 논쟁·대상/발언자 선택만 제공하고 분석마다 별도 URL로 이동한다. 문서는 핵심 쟁점·예상 찬반 논리·실제 발언을 구분하며 사용자 수정·근거 필터 후 명시적으로 분석을 시작한다. 수정·실행에 낙관적 revision을 적용했다. 기존 통계와 어댑터/DI는 재사용했다. 실제 원본에 이름이 없어 UUID 기반 고정 합성 이름을 표시하고 이름 오른쪽에 색상 입장 배지를 둔다. 신규 검토 SQL은 로컬만 준비했다. [최신 계약](AI/persona-debates.md)을 따른다. 파일 이동·삭제·새 앱 의존성·커밋·푸시 없음.

## 페르소나 필터 후보 검토 · 2026-11-02

전체5만 건을 읽기 전용으로 조사해 [필터 검토 문서](database/persona-filters.md)를 작성했다. 기본6종(연령·성별·시도·학력·혼인·동거), 검색형 직업 등 고급 조건을 제안한다. 직업 희소 범주·소득 없음·취미 목록의 문자열 형식·지역 표시 매핑5개·본문의 원래 합성 이름을 확인했다. 기존 이름 부재 안내를 정정했다. 구현/원격 스키마 변경은 하지 않았고 실제 이름 추출 검증과 필터 개편은 사용자 판단 뒤 후속 작업이다.

## 실제 스키마 필터·DB API · 2026-11-02

기본6종·고급5종으로 개편하고 소득 제거·직업 서버 검색50개씩·시도별 시군구·본문 합성 이름을 연결했다. 모든 항목은 빈 배열 전체 선택, 개별 선택 시 전체 해제다. 표본50명 이하이면 JEV 없음 안내를 표시한다. `PersonasModule`의 선택지/미리보기/목록/표본 API를 `PersonaSource` 인터페이스·Supabase 어댑터/DI로 분리해 논쟁 모듈과 공유한다. 기존 파일 이동·삭제·새 런타임 의존성 추가는 없다.

원격3개 SQL 적용 완료, 기존 관리자 키 방식은 제거했다. 기존 공개 키·사용자 JWT와 DB 소유권 검사로 동작한다. [DB 적용 버전·권한](database/schema.md), [HTTP 계약](backend/api.md)을 따른다. 이전 연결 대기·서버 키 설정 기록은 과거 상태다. 커밋·푸시 미실행. 사용자가 팝오버가 아닌 상시 사이드바를 정정 요청해 입력 오른쪽에 대상/발언자를 함께 두며 모바일에는 입력 아래로 이어지게 변경했다. 결과 내 조건도 인라인 패널이다. 최종 증빙 `.tmp/debate-qa/sidebar-v4.png`(합성 API·실제 UI).

## 브랜치와 커밋 규칙

- 브랜치는 마일스톤과 기능을 기준으로 `codex/m<번호>/<기능>` 형식으로 나눈다. 기능명은 짧은 영문 소문자와 하이픈을 사용한다. 예: `codex/m0/context-harness`, `codex/m1/turborepo-setup`, `codex/m1/docker-dev`, `codex/m2/conversation-upload`.
- 한 브랜치는 하나의 마일스톤 안에서 일관된 기능을 다룬다. 독립적인 기능은 분리하고, 같은 기능을 완성하는 여러 작은 커밋은 같은 브랜치에 둔다. 기반 작업에 의존하는 브랜치는 기반 병합 후 시작하거나 의존 관계를 명시한다.
- 커밋은 한 작업 단위로 세세하게 나눈다. 예: Git 추적 규칙, workspace 설정, React 초기화, NestJS·Swagger 초기화, Docker 개발 환경, 검증·문서 갱신. 서로 무관한 변경을 한 커밋에 묶지 않는다.
- 커밋 메시지는 `<type>(<scope>): <한국어 작업 요약>` 형식을 사용한다. type은 `feat`, `fix`, `chore`, `docs`, `test`, `refactor` 중 작업에 맞게 고르고 scope는 `repo`, `frontend`, `backend`, `database`, `ai`, `infra` 중 해당 영역을 쓴다.
- 예: `chore(repo): 임시 파일과 의존성 추적 제외`, `chore(repo): pnpm과 Turborepo 작업 구성`, `feat(backend): 상태 확인 API와 Swagger 추가`, `chore(infra): Compose 개발 환경 구성`.
- 작게 나누더라도 필요한 설정·의존성·잠금 파일을 함께 포함해 작업 단위가 재현 가능해야 한다. 기능에 필수인 검증과 계약 수정은 같은 커밋에 포함할 수 있다.
- 커밋 전 `git status --short`와 스테이징 diff를 확인하고 의도한 파일만 경로를 지정해 스테이징한다. unrelated 변경을 포함하는 `git add .`를 기본으로 사용하지 않는다. 해당 작업에 필요한 검증 결과를 확인한다.
- `.agents/`, README, 설정 예제, `pnpm-lock.yaml`은 추적한다. `.tmp/`, node_modules, 빌드·캐시·로그·실제 환경 설정·비밀 키는 `.gitignore`로 제외한다. 로컬 Docker와 호스트 모두에 이 규칙을 적용한다.
- 실제 브랜치·커밋 작업 시 현재 브랜치와 사용자 변경을 먼저 확인한다. 사용자가 지정한 브랜치명은 우선한다. 브랜치 삭제·강제 푸시·기존 커밋 재작성은 별도 지시 없이 수행하지 않는다.

## 프론트 OAuth 연결 · 2026-10-03

프론트 하네스를 읽고 기존 로그인 폼을 Google·GitHub·Kakao 공식 리소스 진입점으로 교체했다. SDK 2.117.2 고정 설치, 브라우저 PKCE·단일 코드 교환·Auth Context·내 정보 GET/PATCH·로그아웃·상단 계정 표시·콜백 실패 재확인을 구현했다. 기존 대화 화면의 합성 데이터 체험을 유지하며 실제 대화 저장·분석 연결로 표시하지 않는다. 원격 Auth 제공자·DB 설정은 이번 작업에서 변경하지 않았다.

사용자 명시 요청으로 테스트와 타입·lint·빌드·브라우저·컨테이너 실행을 하지 않았다. [화면 및 수동 확인](frontend/screens.md#oauth-로그인-연결--2026-10-03), [공식 리소스](../apps/frontend/public/auth/README.md), [공개 설정](infra/guide.md#프론트-oauth-공개-설정--2026-10-03)을 참조한다. 로그인 상태는 Context Provider로 공유하고 SDK·API 경계를 화면과 분리했다. 사용자 요청으로 변경 사항을 작업 단위 커밋으로 저장하며 원격 푸시는 하지 않는다.

카카오 로그인은 사용자 성공 보고 및 기존 원격 Auth 로그의 PKCE 200을 확인했다. Google은 invalid_client(Client Secret 불일치), GitHub는 이메일 API 403(Resource not accessible by integration)을 확인했다. 에이전트 로그인 테스트·원격 설정 변경은 하지 않았다. Google·GitHub 수정 후 성공은 미확인이므로 OAuth 전체 완료로 표시하지 않는다. 상세 조치는 [인프라 기록](infra/guide.md#oauth-수동-확인과-오류-조사--2026-10-03)에 저장했다.
