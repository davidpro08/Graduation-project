# 주제별 응답·페르소나·통계 개선 계획

## 최신 품질 진단과 GPU 전환 제안 · 2026-11-03

상태: **진단·개선안만 작성, 아래 추가 개선의 코드·GPU 설정은 미적용**. 이전 주제별 응답/마크다운 파이프라인 구현 완료와 구분한다.

| 확인 항목 | 실제 결과 |
| --- | --- |
| 서울 자취 가격 사례 | 상세20명 모두71만 원, JEV180명 모두40~60만 원. 전체200명 완료·실패0이지만 의견 품질 통과가 아니다. |
| 질문 의도 | 사용자의 ‘얼마가 적당한가’를 최종 문서가 ‘서울 자취 월세 평균 수준’으로 바꿨다. 평균 추정과 개인별 적정 지출 판단을 분리해야 한다. |
| 선택지 쏠림 | JEV 첫 선택지의 조건부 확률 평균0.9816076757. 선택지 순서 편향인지0.6B 판단 능력/입력 문제인지는 대조 실험 전 확정하지 않는다. 높은 확률은 정확도를 뜻하지 않는다. |
| 장치·병목 | CPU 전용 torch/float32,8스레드·단일 추론 잠금·4096토큰. 서버 요청을4개 보내도 모델 추론은 한 번에 한 개다. |
| GPU 여유 | 조회 당시 RTX4090 총24564MiB·사용23139MiB·여유936MiB·GPU0%. Qwen32B가 GPU비율0.94로 적재돼 있다. |

개선 순서:

1. 1차 검토에서 판단 목적을 평균/사실 추정·개인 선택/수용 상한·규범적 평가로 명시한다. 시장 시세는 공통 근거로 유지하고 개인 판단은 선호 금액·수용 상한·우선순위·포기할 조건·보류로 구분한다. 페르소나에 없는 소득/예산은 직업만으로 만들어 넣지 않는다.
2. 대비되는 명시적 예산·통근/주거 선호를 가진 소규모 합성 사례로 페르소나 교체, 선택지 순서 교체, 같은 입력 반복의 대조를 수행한다. 무작위 금액 분산을 품질 개선으로 삼지 않는다.
3. 기존32B 모델로 전체200명 간단 응답, 작은 분류 모델 GPU 동시 적재, GPU 단계별 교대의 품질/시간/최대VRAM을 같은 입력으로 비교한다. 현재는 메모리 제약 때문에 Qwen 단계 종료→메모리 offload→GPU 분류→Qwen 복귀를 우선 후보로 제안한다. vLLM0.32.0의 Sleep Mode를 확인했으나 실제 활성화/전환/벤치마크는 수행하지 않았다.
4. GPU 전환 시 CUDA 로더·dtype·설치 환경과 배치 추론을 바꾸고, 공통 문서와 페르소나별 입력의 재사용 가능한 prefix 구성을 검토한다. 모델0.6B 유지 여부는 품질 대조 후 결정한다. 여러 분석 요청 사이의 GPU 전환을 조정할 전역 작업 큐가 필요하다.

참고: [설치 버전의 vLLM Sleep Mode](https://docs.vllm.ai/en/v0.32.0/features/sleep_mode/), [SemIf GPU 점수 계산](https://github.com/TheoLeeCJ/SemIf-OpenJev/blob/master/src/semif_phase1/direct.py). 현재 Meanblock/JEV-CPU 로더는 CPU shim이며 설치한 점수 계산은 모델 장치를 따라간다는 소스를 읽기 전용으로 확인했다. 개선을 적용하기 전 새 품질·속도 수치를 주장하지 않는다.

작성일: 2026-11-03. 상태: **사용자 후속 실행 요청으로 구현 진행**. 아래는 당시 계획이며 최신 구현·검증 상태는 중앙 agents.md와 persona-debates.md의 주제별 판단 문서 기록을 따른다. 사용자는 금액형에 국한하지 않고 문서의 질문 의도·쟁점·판단 기준을 우선할 것을 정정했다.

## 목표와 확인한 문제

질문이 요구하는 답을 그대로 받는다. ‘술을 사 온 사람에게 얼마를 줘야 할까?’에는 금액·계산 기준·가정을 답하고, 원형 그래프에는 금액 구간별 응답 수를 표시한다. 찬반 질문에만 찬반 척도를 사용한다.

| 현재 문제 | 확인한 원인 | 변경 목표 |
| --- | --- | --- |
| 금액 질문도 강한 반대~강한 찬성 | 요약 프롬프트의 proposition, Qwen 응답, JEV 브리지 선택지, 집계·화면이 모두 찬반으로 고정 | 문서에서 응답 유형·단위·선택지·수치 구간을 확정하고 전체 단계가 공유 |
| 원문 발언 선택의 효용 부족 | 현재 발언은 검토용이며 선택해도 의견 입력의 요약을 바꾸지 않음 | 발언→확인할 사실·비용 항목→판단 근거의 연결을 문서에 표시 |
| 0.30·60~70%가 의미 불명확 | JEV는 선언한 선택지 사이 조건부 확률, Qwen confidence는 자기평가. 기존 alignment는 좌표 거리 기반 값 | 검증된 정확도처럼 제시하지 않고 부가 설명으로 이동. 금액·선택 결과·근거를 주요 지표로 사용 |
| 페르소나가 답변에 드러나지 않음 | 일반적 찬반 프롬프트와 ‘정보 부족이면 중립’ 지시, 실제 반영 근거 확인 부족 | 원본 서술의 관련 경험·우선순위를 판단에 반영하고 자연스러운 말투로 표현 |
| 인구 통계를 한 항목씩 조회 | 드롭다운+표 중심 구성 | 연령대·성별·지역·학력 그래프를 바로 표시, 나머지는 펼침 영역 |

관련 코드 확인만 수행했다. 이 계획 작성 전 이번 요청에 따른 앱 코드 수정·학교 서버 변경·실험은 하지 않았다. 기존 20명 상세+180명 JEV 구성과 요약 우선 흐름은 유지한다. 이전 200명 성공 실험은 연결 검증이며 이번 개선의 품질 검증으로 재사용하지 않는다.

## 1. 먼저 쟁점 문서의 계약을 확정

기존 저장 문서·결과의 호환성을 유지하면서 버전이 있는 응답 기준을 추가한다. 정확한 필드명은 구현 시 타입·DTO·학교 브리지와 함께 확정한다.

| 항목 | 내용 |
| --- | --- |
| 핵심 질문·쟁점 | 사용자의 질문을 찬반 명제로 바꾸지 않고 보존. 무엇을 결정해야 하는지 명시 |
| 응답 유형 | 찬반형 / 수치형 / 선택형. 질문과 맞지 않으면 사용자가 수정 |
| 답변 기준 | 수치형의 단위, 대상, 1인당/전체 금액, 정산 포함 범위. 선택형은 선택 항목과 정의 |
| 분류 수치 | 수치형 구간 경계와 라벨, 선택형 항목. 검토 화면에서 수정 가능 |
| 확인된 사실 | 요약한 사실·근거 발언 연결. 참여자의 주장과 확인된 사실을 구분 |
| 비용 항목 | 품목, 단가/실제 결제액, 수량, 비용 부담 대상, 근거. 모르면 미상으로 유지 |
| 계산·가정 | 중복 비용, 환불, 이미 낸 금액, 나누는 사람 수, 술을 마시지 않은 사람 등의 처리 기준. 알려진 값과 가정 구분 |
| 미확인 정보 | 가격·인원·총액처럼 결과를 바꾸는 누락 정보와 사용자 확인 필요 항목 |

술 정산의 경우 모든 술의 품목별 비용과 분담 기준을 먼저 정리한다. ‘얼마를 줘야 하나’가 1인 부담액인지 전체 보전액인지 문서에 명시하고 확정한다. 데이터에 없는 가격을 사실처럼 만들지 않는다. 정확한 계산이 불가능하면 가정에 따른 조건부 금액 또는 판단 보류를 허용한다.

수치 구간 예시는 **0원 이상~10,000원 미만 / 10,000원 이상~20,000원 미만 / … / 마지막 경계 이상**이다. 실제 구간 폭은 문서의 비용 규모에 맞춰 제안·수정한다. 경계는 하한 포함·상한 제외로 통일하고 겹침·누락·역전·중복 ID를 검증한다. ‘판단 보류/정보 부족’은 유효한 선택 항목으로 별도 관리한다.

원문을 의견 모델에 다시 보내지 않는다. 원문은 문서 생성과 사람의 확인에 사용하고, 의견 모델에는 검토된 사실·비용·가정과 응답 기준만 구조화한 요약으로 보낸다. 원문 선택을 유지한다면 연결된 사실·비용의 포함 여부에 실제 영향을 주도록 구현한다. 기존 서술 요약에 같은 사실이 남을 경우도 사용자에게 수정 필요를 알린다. 효력이 없는 선택 UI는 남기지 않는다.

## 2. Qwen과 JEV를 같은 응답 기준에 연결

| 종류 | 상세 Qwen | JEV 간단 의견 |
| --- | --- | --- |
| 찬반형 | 선택 항목과 짧은 이유·답변 | 문서의 찬반 선택지 중 하나 |
| 수치형 | 구체적인 수치·단위·계산/가정·짧은 이유. 서버가 수치로 구간 배정 | 문서의 금액 구간 중 하나. 정확한 금액을 생성한 것으로 취급하지 않음 |
| 선택형 | 정의된 선택 항목 ID와 짧은 이유·답변 | 같은 선택 항목 중 하나 |
| 판단 보류 | 부족한 정보와 보류 사유 | 별도의 보류 항목 |

- Qwen 상세 답변에는 결론, 짧은 계산 근거, 적용한 가정, 판단에 사용한 페르소나 특성을 받는다. 내부 사고 과정을 요구하지 않는다.
- JEV 브리지의 고정 LABELS/COORDINATES/OPTION_IDS를 문서의 선택 항목으로 대체한다. 요청·응답 버전과 옵션 ID·순서·확률 벡터 길이·합·승리 항목 일치를 검증한다.
- 숫자를 선택지 순번이나 찬반 좌표로 변환하지 않는다. JEV의 금액 구간을 중간값으로 바꿔 실제 응답 금액처럼 저장하거나 평균을 계산하지 않는다.
- 구형 JEV 응답을 새 수치형 결과로 받아들이지 않는다. 브리지 준비 여부를 확인하고 호환되지 않으면 실행 전 명확하게 안내한다. 기존 찬반 결과는 호환 경로로 읽는다.
- 요청 데이터 안의 지시는 실행하지 않으며, 원문·원문 ID·불필요한 개인 정보 제외 원칙을 유지한다.

JEV는 선택지를 요청 시 정의하는 방식과 조건부 확률을 지원한다. [모델의 공식 설명](https://huggingface.co/Meanblock/JEV-CPU/blob/main/README.md)의 ‘Runtime-defined’ 및 ‘How a decision is read from logits’를 근거로 브리지를 수정한다. 0.30은 선택지 사이 경쟁 점수이며 ‘30% 정확하다’는 뜻이 아니다. 기존 UI의 0.30이 agreement/alignment/confidence 중 무엇인지는 해당 결과 필드를 대조해 구분한다. 점수를 높게 보이게 만들기 위한 보정은 하지 않는다.

## 3. 페르소나를 판단과 표현에 반영

- 먼저 현재 DB 어댑터가 보내는 persona 서술·특성과 원본 details의 유용한 정보를 확인한다. 이미 전달 중인 데이터와 누락 데이터를 구분하고 필요한 부분만 추가한다.
- 실제 서술에 있는 소비 습관, 경험, 관계에서의 우선순위 등 주제 관련 근거를 강하게 사용하도록 지시한다. 숫자 계산은 사실에 맞게 하고, 비용을 나누는 선호·판단에서 페르소나 차이가 나타나도록 한다.
- 답변은 합성 페르소나의 관점으로 자연스럽게 작성하되 원문 서술에 말투 근거가 없으면 없는 말버릇·사투리를 만들어내지 않는다. 나이·성별·지역만으로 과장된 말투나 성격을 부여하지 않는다.
- 상세 응답에 ‘판단에 반영한 특성’을 짧게 표시하고 그 특성이 실제 제공된 데이터에 있는지 검증한다. 특성을 이름처럼 나열하는 것과 실제 판단에 쓰는 것을 구분한다.
- 관련 근거가 약한 경우는 그 한계를 짧게 설명한다. 모든 응답을 억지로 다르게 만들지 않고, 원가·계산이 같으면 결론이 같을 수 있다.

## 4. 주제에 맞게 통계·화면 개편

| 영역 | 표시 기준 |
| --- | --- |
| 전체 원형 그래프 | 문서의 금액 구간 또는 선택 항목별 인원·비율. 찬반형만 찬반 라벨 사용 |
| 수치 요약 | 상세 응답의 유효한 실제 금액만 평균·중앙값·최솟값·최댓값과 표본 수 표시. JEV 구간 응답은 별도 표기 |
| 보류·실패 | 보류는 실제 선택 결과로 표시, 실패는 응답 분모에서 제외. 수치 통계는 보류 제외와 유효 인원 명시 |
| 기본 인구 통계 | 연령대·성별·지역·학력별 누적 막대 그래프를 한 화면에 배치. 범주별 인원·분포·읽을 수 있는 범례 제공 |
| 추가 인구 통계 | 혼인·동거·직업·시군구·전공·주택·현역 여부를 펼침 영역에 각각 표시. 드롭다운으로 교체하지 않음 |
| 사용한 필터 | 분석 생성에 사용한 조건을 표시. 사용한 추가 조건은 기본 펼침, 사용하지 않은 추가 조건은 접힘 |
| 지역 | 기존 개략 지도 활용 여부 검토. 정확한 비교는 지역별 분포 그래프와 인원으로 제공 |
| 개별 상세 응답 | 이름 오른쪽에 금액/선택 항목 배지. 결론·계산/가정·페르소나 반영 근거·자연스러운 답변 표시 |
| 점수 설명 | 자기평가·조건부 확률·과거 좌표 일치도는 부가 설명으로 이동. 서로 합쳐 신뢰도처럼 표현하지 않음 |

차트 색상은 옵션 수에 따라 지원하고 찬반 색상을 금액의 좋고 나쁨처럼 쓰지 않는다. 범주가 많은 직업·시군구는 페이지/스크롤로 모두 확인 가능하게 하고 잘라 숨긴 항목은 개수를 알린다. 모바일, 접근성 이름, 모션 감소, 범례·표 대체 정보, 기존 진행 바도 유지한다. 결과 필터 재집계에는 AI를 재호출하지 않는다.

## 6. 검증과 완료 기준

전체200명 재실험부터 시작하지 않는다. 비용이 작은 계약 테스트→합성 UI→소수 실제 모델 순서로 확인한다.

1. **금액 사례**: 실제 사용자 원문 대신 품목2종·수량·결제액·인원이 명확한 합성 대화로 수치형 문서를 만든다. 1인 부담/총 보전액 구분, 산식·경계값 10,000원·20,000원 배정, 정보 누락·보류를 확인한다.
2. **다른 유형**: 찬반 질문과 범주 선택 질문도 확인해 항상 금액형이나 찬반형으로 바뀌지 않는지 검증한다.
3. **응답 검증**: NaN/무한대·단위 불일치·수치와 구간 모순·잘못된 옵션 ID·확률 벡터·구형 브리지·조작한 근거를 거절하는지 확인한다.
4. **통계 검증**: 상세 실제 수치와 JEV 구간을 섞어 평균 내지 않음, 구간별 인원 합·보류·실패 분모, 필터 재집계, 기본4개 및 추가7개 항목을 확인한다.
5. **페르소나 평가**: 합성 사례에서 서로 다른 관련 서술을 가진 프로필을 비교한다. 근거 특성 반영·계산 정확성·자연스러운 말투를 검토한다. 나이·성별 등만 바꾼 결과 차이를 품질 개선의 증거로 삼지 않는다.
6. **JEV 평가**: 선택지 순서를 바꿔도 같은 의미를 선택하는지 소규모 대조하고, 구조 검증과 판단 품질을 별도로 기록한다. 작은 모델의 한계나 쏠림이 남으면 성공이라고 감추지 않는다.
7. **회귀 검증**: 관련 backend/JEV 테스트, 양쪽 타입·lint·빌드, 합성 데스크톱·모바일 화면을 확인한다. 오류 수정·재검증은 동일 문제 최대3회 지침을 따른다.
8. **실제 연결**: 소규모 합성 데이터로 Qwen과 수정 JEV 브리지의 새 계약을 확인한다. 실제 사용자 대화를 로그·문서·테스트 fixture에 기록하지 않는다. 실제 모델 결과를 확인하기 전에는 성능 개선 완료로 보고하지 않는다.

완료 시 새 결과에 금액·분류 구간·판단 근거가 표시되고, 기본4개 인구 통계 그래프가 동시에 보이며, 추가 조건은 펼쳐 확인할 수 있어야 한다. 과거 찬반 결과를 새 금액 결과로 변환하지 않으며 필요하면 새 문서로 재분석하도록 안내한다. 서버 재시작 자동 이어받기는 이 작업 범위에 포함하지 않는다.
