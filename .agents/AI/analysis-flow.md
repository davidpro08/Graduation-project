## 모순 경로 교체 · 2026-11-07

모순은 Qwen 명제 추출→DB 저장/재조회→JEV 쌍별 분류로 전환했다. [현재 설계·검증](claims-plan.md)을 우선한다. 아래 직접 Qwen 분석/구간 복구 설명은 일정 경로에 유지되며 모순 경로의 과거 동작과 구분한다. 운영 DB·학교 서버에는 미적용이다.

## 후보 표현·대화 흐름·오류 복구 · 2026-11-02

이 절이 아래의 이전 분할·전체 실패 정책보다 우선한다. 최근 한 달 범위는 유지한다.

| 영역 | 현재 처리 |
| --- | --- |
| 모순 | title(짧은 요약)·기존 summary·근거를 반환. 제목 없는 과거 결과는 본문 첫 문장으로 표시 |
| 대화 흐름 | 날짜·발언 순서·시각을 보존해30분 이내 세션으로 묶는다. 일정 요청은 세션 경계를 지키고, 큰 묶음은 약7KB/40개 메시지 단위·긴 발언은1800문자로 분할 |
| 경계 문맥 | 같은 세션에서 크기로 나눌 때 직전 발언 하나를 겹쳐 전달. 서로 먼 구간의 연결까지 보장하지 않음 |
| 근거 | 모델 입력의 UUID를 m1 등 짧은 별칭으로 바꾸고 응답 후 원문 UUID로 복원. 현재 입력에 없는 근거·모순의 서로 다른 근거2개 미만은 거절 |
| 모델 출력 | JSON, 낮은 temperature0.1·최대1024토큰. 토큰 한도에서1088토큰 여유를 확보. 후보8개 초과를 알리는 moreCandidates=true이면 재분할 |
| 일정 추정 | date/time/uncertain을 선택적으로 반환. 원문의 dateTimeText를 유지하고 근거 발언 기준 규칙 계산을 우선. 부족한 값은 AI 추정 또는 발언 날짜/시각·아침09/점심12/오후15/저녁18/밤21시로 임시 제안 |
| 불확실 표시 | fallback·AI 추정·모호한 표현·규칙 경고는 suggestion.uncertain=true와 이유를 저장. 빨간 카드/날짜/시간·확인 필요 표시. 사용자 확인 후에만 confirmed·starts_at/ends_at 저장 |
| 중복 후보 | 같은 제목/날짜·근거 포함 관계의 부분 후보는 더 완전한 후보로 합친다. 같은 세션의 `제목+장소` 후보가 날짜/시간 모두 임시값이고 연결할 약속이 하나일 때만 장소 근거를 합친다. 별도 시각·별도 근거나 복수 대상이면 유지 |
| 재시도 | 구간별 최초 포함2회. 연결/90초 응답 만료/429 및 형식·근거·미완성 응답 재시도. 컨텍스트 초과는 즉시 분할. 신호 취소·인증·설정·DB 오류는 무차별 재시도하지 않음 |
| 재분할 | 형식·근거 오류가 반복되면 추가2단계까지 작은 구간으로 분할. 컨텍스트/후보 초과 분할은 최대12단계. 더 나눌 수 없으면 실패 구간을 기록 |
| 연결 장애 지속 |3개 구간 연속 연결 계열 실패 시 같은 작업의 나머지 모델 요청을 중단해 요청 폭주를 줄이고 미처리 범위를 기록 |
| 부분 결과 | 한 구간 이상 성공했으면 coverage=partial로 유효 결과만 저장하고 실패 구간/경고를 표시. 빈 후보도 정상 응답이면 성공 구간. 전 구간 실패는 failed |
| 저장 상한 | 검증된 고유 후보 최대1000개. 초과 시 truncatedItems와 경고·partial을 남기며 조용히 전체 성공으로 표시하지 않음 |
| 화면 상태 조회 | 일시적 조회 장애는2~15초 간격으로 자동 재조회. 새 모델 분석을 자동 중복 생성하지 않으며401/403/404는 재조회 중단 |

새 완료 metadata는 기존 필드와 함께 `coverage,successfulChunks,failedChunks,retries,splits,failures,truncatedItems`를 포함한다. `failures`는 날짜·시각 범위/메시지 수/오류 코드만 포함하고 원문·인증 정보를 담지 않는다. AI_REQUEST_TIMEOUT은 개별90초 응답 대기 만료, AI_BUSY는429로 AI_UNAVAILABLE과 구분한다. 작업 전체 기본2시간 제한은 그대로다.

일정의 suggestion은 analysis_jobs.result.items 안에 저장하고 schedules.item_index로 복원한다. 따라서 새 컬럼 없이 추정값과 경고가 새로고침 후 유지된다. `complete_analysis`는 partial일 때 이전 proposed를 지우지 않고 같은 제목·원문 표현·근거의 중복을 추가하지 않는다. 완전한 재분석은 기존대로 proposed를 교체하며 confirmed는 항상 보존한다. 부분 결과는 작업 종료 시 저장하며, 중간 체크포인트·백엔드 재시작 후 이어받기·공유 큐는 아직 없다.

분할과 복구는 AnalysisRunner, 세션/크기 분할은 analysis-chunks, 일정 추정은 schedule-candidate의 순수 함수로 분리하고 기존 Qwen/Supabase Adapter·DI를 유지했다. 근거가 실제로 맞는지·취소나 반복 약속을 정확히 이해하는지에 대한 품질 평가는 계속 필요하다.

검증: 양쪽 lint·빌드와 프론트 타입 통과. 전체 백엔드93개 통과 후 장소 확인 병합 보완을 포함한 최종 분석 회귀26개 통과(현재 테스트 목록94개). 격리 PGlite 및 실제 DB 롤백에서 부분 후보 보존·중복 방지·확정 보존·전체 교체·제목/추정 JSON·멱등성·소유권/권한을 검증했다. 원격 합성 대화 잔존0건, 보안 advisor 신규 지적 없음. 실제 사용자 로그인→HTTP→DB 전체 경로는 이번 검증에서 재실행하지 않았다.

학교 Qwen 합성 모순/일정은 완료했고, 추가 일정3사례는 최종적으로 분리된 날짜/시간/장소→회의1건(8.610초), 다음 주·저녁 추정→경고 있는 후보1건(5.235초), 뒤에서 취소한 약속→후보0건(0.886초)을 통과했다. 첫 시도에서 같은 회의의 중복 후보와 모델의 요일 계산 오류를 관측해 보정했다. 작은 합성 사례의 성공을 전체 정확도로 일반화하지 않는다. 기록은 Git 제외 `.tmp/gpu-ai/schedule-flow-report.json`, 중간 실패 기록은 schedule-flow-report-v2.json이다.

실제 화면 컴포넌트+합성 API로19px/15px 제목·본문,1px 원문 버튼, 빨간 카드/날짜/시간 선택기, 확인 후 확정,390px 가로 넘침 없음, partial 실패 기간을 확인했다. 화면 기록은 Git 제외 `.tmp/debate-qa/contradictions-final.png`, schedules-final.png, schedules-mobile.png다. 검증용 탭·서버를 종료하고 임시 viewport를 원복했다. 학교 모델·SSH 터널·사용자 개발 서버는 유지했다.

## 최근 한 달 분석 · 2026-11-02

모순·일정의 새 작업은 대화 `endDate`를 기준으로 달력상 한 달 전부터 마지막 날짜까지 양 끝 날짜를 포함한다. 실행 당일이 아닌 대화 날짜를 사용하므로 과거 대화도 분석할 수 있다. 예: 마지막 날짜2026-11-02이면2026-10-02~2026-11-02,2024-03-31이면2024-02-29~2024-03-31이다. 월말은 전월의 마지막 유효 날짜로 보정한다.

| 항목 | 이전 | 현재 |
| --- | --- | --- |
| DB 조회 | 전체 메시지200개씩 | 기존 from/to 필터로 기간 내 메시지만200개씩 |
| 모델 입력 | 전체 text | 기간 내 text만. 첨부·시스템 제외, 토큰 검사·분할 유지 |
| 기록 | 모델·구간·경고 | 추가 metadata.inputRange={from,to,anchor:'conversation_end',messageCount} |
| 화면 | 일반 분석 안내 | 대화 마지막 날짜 기준 안내·완료 결과의 실제 기간/텍스트 수. 범위 기록 없는 이전 결과는 재분석 안내 |
| 빈 기간 | 별도 구분 없음 | 모델 미호출·빈 후보와 경고. 과거로 범위를 자동 확대하지 않음 |

기존 저장소 인터페이스·Qwen/Supabase Adapter·DI를 유지하고 날짜 계산을 순수 함수 `analysis-window.ts`로 분리했다. DB 스키마·RLS·기존 확정 일정·페르소나 분석 범위는 변경하지 않는다. 기존 결과를 소급 재분석하지 않으며 새 작업부터 적용한다.

최근 한 달 제한만 적용했던 시점에는90초 요청 만료와 연결 장애를 AI_UNAVAILABLE로 합치고 한 구간 실패도 전체 실패로 처리했다. 이후 위 오류 복구 정책으로 보완했다. 분량만이 단일 실패 원인이라는 증거는 아니다.

현재 모델/8192토큰 기동 정보는 [GPU 실험 기록](gpu-experiments.md)이 아래2026-10-03의2048토큰 측정보다 우선한다. 모순·일정은 Qwen을 직접 사용하며 JEV-CPU는 페르소나 간단 의견만 담당한다.

아래는2026-10-03 최초 구현 기록이며 기간 제한은 위 최신 규칙을 따른다.

| 단계 | 실제 동작 |

분할 구간을 가로지르는 모순은 누락될 수 있으며 화면에 한계를 표시한다. 정확도 평가·장거리 모순 연결·구간 중첩은 후속 작업이다. 결과를 사실로 단정하지 않는다.

## API 실제 계약

모든 경로는 `/api` 접두사와 Bearer 인증을 사용한다. UUID는 v4다.

| API | 계약 |
| --- | --- |
| POST `/conversations/:id/analyses` | `{type:"contradiction" 또는 "schedule"}`. 기존 `useJev` 필드는 400으로 거절, 202로 작업 객체 반환 |
| GET `/conversations/:id/analyses?type=` | `{job:작업 또는 null}`. 본인 마지막 작업만 조회 |
| GET `/analyses/:id` | `id,conversationId,analysisType,status,errorCode,createdAt,updatedAt,result,metadata` |
| GET `/analyses/:id/result` | 완료 시 `{items,metadata}`, 완료 전 409 |
| GET `/conversations/:id/schedules` | 후보·확정 일정 배열, 최대 1,000개 |
| POST `/schedules/:id/confirm` | `{title,date:"YYYY-MM-DD",time:"HH:mm"}` 필수. 중복 행 생성 없이 같은 ID 갱신 |
| PATCH `/schedules/:id` | 같은 입력. confirmed만 수정 |
| GET `/conversations/:id/messages?messageId=` | 소유권·대화 일치 확인 후 해당 근거의 원문 페이지 반환. 다른 필터 해제 |

모순 항목은 `{title,summary,evidenceMessageIds}`이며 서로 다른 근거2개 이상이다. 일정 항목은 `{title,dateTimeText,evidenceMessageIds,date?,time?,uncertain?,suggestion?}`이며 근거1개 이상이다. 결과 metadata의 최신 필드와 partial 처리 규칙은 맨 위 절을 따른다. 과거 작업에는 신규 필드가 없거나 jevUsed/skippedChunks가 남을 수 있다.

작업은 백엔드 프로세스 메모리에서 실행한다. 토큰은 실행 중 메모리에만 유지하고 DB에 저장하지 않는다. 소유자의 상태 조회에서 검증된 최신 토큰으로 작업 토큰을 갱신한다. 화면을 닫아 갱신 요청이 없거나 DB 장애가 발생하면 장기 작업이 실패할 수 있다. 한 프로세스에서 최대 4개 작업을 허용한다. 같은 대화·종류의 진행 작업은 DB 유일 인덱스로 차단한다. 재시작 후 실행자가 없는 pending/processing은 사용자 조회 시 `JOB_INTERRUPTED` 실패로 복구한다. 다중 백엔드 배포 전에는 공유 작업 큐·worker를 도입해야 한다.

실패 코드는 `AI_CONFIG_ERROR`, `AI_CONTEXT_ERROR`, `AI_AUTH_ERROR`, `AI_UNAVAILABLE`, `AI_INVALID_RESPONSE`, `AI_INVALID_EVIDENCE`, `AI_INCOMPLETE_RESPONSE`, `ANALYSIS_TIMEOUT`, `ANALYSIS_TOO_LARGE`, `ANALYSIS_FAILED`, `JOB_INTERRUPTED`다. 원격 오류 본문·키·원문을 오류 로그에 출력하지 않는다. 대화 삭제 후 FK와 RPC 조회가 늦은 결과의 재생성을 막는다.

## DB

`analysis_jobs`는 대화·소유자 복합 FK, 작업 종류·상태·결과·메타데이터·시각을 저장한다. `schedules`는 작업·대화·소유자 복합 FK, 원문 날짜·근거 배열·proposed/confirmed·starts_at을 저장한다. 대화 삭제 시 연쇄 삭제한다. SECURITY INVOKER RPC는 근거 메시지가 같은 대화·소유자에 속하는지 검증한다. 재분석은 이전 proposed 후보를 교체하고 confirmed 일정을 유지한다. 같은 작업 완료 호출은 반복해도 결과·일정이 중복되지 않는다.

로컬 SQL은 `supabase/migrations/20261003113704_ai_analyses.sql`, 원격 MCP 적용 이력은 `20261003115026_ai_analyses`다. MCP가 적용 시각으로 버전을 부여했다. 원격 SQL은 이미 적용했으므로 같은 SQL을 `db push`로 다시 적용하지 않는다. 다음 CLI 배포 전 로컬·원격 이력 매핑을 정리해야 한다. 기존 사용자 파일 이동·원격 이력 수정은 수행하지 않았다.

RLS·공개 권한 회수·FK 인덱스 검사 완료. 신규 테이블의 보안·미인덱스 FK 지적은 없다. 기존 Auth 유출 비밀번호 보호 경고와 페르소나 정책 없음 INFO는 기존 상태다. ## 과거 검증 기록

아래는 제거 전 TypeSafe JEV를 사용한 2026-10-03 검증 이력이다. 현재 코드나 jev-cpu 연결의 검증 결과가 아니다. 현재 `check:analysis-pipeline`은 합성 데이터로 Qwen만 호출한다.

`check:analysis-pipeline`은 실제 JEV·Qwen과 운영 분석 서비스를 합성 메모리 저장소로 확인한다. 실제 두 종류 모두 completed·근거 ID·모델 확인, 약 3초. DB 테스트는 합성 데이터로 RLS·완료 RPC 반복·일정 확정/수정·위조 근거 거절·원자성·대화 연쇄 삭제 확인 후 롤백했다. 합성 Auth 계정은 잔존하지 않는다.

브라우저 파일 업로드는 Chrome 확장의 파일 URL 접근 비활성으로 막혔다. 기존 로그인 계정에 `[검증용 합성] JEV·Qwen 화면·DB` 대화를 DB import RPC로 별도 생성해 화면·분석·저장 검증에 사용한다. 실제 원본 TXT는 업로드하지 않았고 대화 안내에도 표시했다. 원본 업로드 검증과 분석 저장 검증을 구분한다.

실제 로그인된 Chrome에서 모순·일정 각각 분석 버튼 → JEV → Qwen → completed → DB 저장 → 화면 표시를 확인했다. 일정 후보를 2026-10-09 15:00 한국 시간으로 확정하고 제목·16:00으로 수정한 뒤 새로고침 복원도 확인했다. 실제 터널 단절 시 failed/AI_UNAVAILABLE와 실패 안내 확인, 확정 일정 보존 확인, 터널 복구 후 모델 목록 정상 응답 확인. 인증 실패는 HTTP Adapter 모의 401로 확인했다(실제 학교 API는 인증 미설정). 백엔드 40개 테스트·양쪽 타입/lint·Nest와 Next 프로덕션 빌드 통과. 당시 사용한 JEV 진단 스크립트는 제거했으며 `supabase/tests/analyses.sql`은 남아 있다.

## 긴 대화 제한 오류 수정

사용자의 `ANALYSIS_TOO_LARGE` 보고를 확인했다. 초기 구현은 분할 구간이 200개를 넘으면 전체 작업을 실패시켰다. 구간 수 제한을 제거하고 시간 제한을 설정 가능한 기본 2시간으로 조정했다. JEV 판단을 먼저 실행해 생략 구간의 학교 API 호출도 없앴으며 토큰 재분할은 사전 판단을 재사용한다. 화면은 분량·시간 초과·재시작·인증·연결 실패를 서로 다른 안내로 표시한다. 기존 TOO_LARGE 작업은 다시 분석해야 한다.

## 일정 날짜·시간 제안 · 2026-10-03

후보 조회 시 근거 메시지의 원래 한국 날짜·시간을 기준으로 날짜를 계산한다. 실행 시각은 사용하지 않는다. 원문 날짜 표현이 실제 메시지에 포함되면 해당 표현을 사용하고, 그렇지 않으면 날짜 표현이 있는 근거 본문을 사용한다. 확정된 사용자 입력은 유지한다. 날짜 계산은 독립 함수로 분리하고 기존 Adapter·DI 구조를 유지했다.

| 표현 | 계산 규칙 |
| --- | --- |
| 금요일 4시반~5시반 | 발언 시점의 주 금요일, 시작 시각이 지났으면 다음 주 |
| 이번/다음/다다음/지난 주 | 월요일 기준 주 이동; 이번 주의 지난 시각은 다음 주 |
| 오늘·내일·모레·글피 | 발언 날짜 기준 일 이동 |
| 다음 달·이번 달의 일자 | 발언 월 기준; 일자만 있고 지난 시각이면 다음 달 |
| 명시한 연·월·일 | 과거라도 임의 이동하지 않음 |
| 오전·오후 없는 1~12시 | 오후 제안과 확인 경고; 자동 확정하지 않음 |
