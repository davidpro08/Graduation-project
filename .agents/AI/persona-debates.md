## 빠른 검색 초안으로 전환 · 2026-11-03

사용자 정정으로 전체 대화 페이지 순회·구간별 누적 요약·재귀 분할을 문서 생성에서 제거했다. 기존 messages search API로 질문에서 추출한 최대6개 핵심 단어를 첫40개씩 제한 조회한다(동시3개). 단일 발언자는 DB 조건에도 적용하고 복수 발언자는 후보에서 제한한다. 중복·무관·제외 화자를 제거하고 관련도순 최대16개/약6KB의 단어 주변 발췌만 한 번에 Qwen에 보낸다. 조회한 후보가 없으면 대화 없이 질문만 정리한다. 전체 데이터에서 일치가 전혀 없음을 보장하는 검색은 아니며 first-page 제한과 복수 화자 희소 조건으로 관련 발언을 놓칠 수 있다. 결과에 검색어·후보 수·참고 수·부분 조사 경고를 표시한다.

AI 호출은 기본1회, 실패 시 입력을 줄여 최대1회 재시도하며 previous=null이다. 재귀 분할·누적/전체 요약은 없다. 모델 단계는60초 대기 제한, 출력1536토큰·짧은 초안 지시를 사용한다. DB 검색 시간은 별도이며 완료 시간을 보장하지 않는다. JEV 관련성 호출은 추가하지 않아 대기 경로를 늘리지 않는다. 기존 인용 검증·주제별 응답 기준·원문 제외 의견 입력은 유지한다. sourceCoverage JSON에 mode=keyword/keywords/matchedMessages/searchFailed를 추가하며 신규 DB 마이그레이션은 없다. 순수 검색/발췌 함수를 document-search.ts로 분리하고 기존 Adapter/DI를 유지했다.

이전의 ‘모든 페이지 조사/구간별 복구’ 문서 기록은 과거 동작이다. 사용자 직접 시험을 위해 실제 AI 요청·학교 서버 변경은 하지 않았다. 새 문서 생성 요청부터 적용한다.


## 문서 근거 품질 보완 · 2026-11-03

사용자 요청으로 문서 품질만 보완했다. **실제 학교 AI 요청·모델 실험·서버 재시작은 실행하지 않고 사용자 직접 시험을 기다린다.** 프롬프트는 질문 의도·사실/참여자 의견/가정/미확인 정보·쟁점·판단 기준을 분리하고 없는 반대 논거나 합의를 채우지 않도록 강화했다. optional factEvidence(최대8개: text/kind/messageId/quote)를 생성하며 reported/opinion의 인용은 실제 현재 구간에 포함되거나 이전 구간에서 확인한 동일 항목이어야 한다. 위조 ID/인용·이전 사실 변형은 AI_TOPIC_EVIDENCE로 거절하고 기존 재시도/분할 정책을 따른다. 가정·미확인 항목에는 원문 근거를 붙이지 않는다.

화면은 항목별 분류·원문 인용·근거 이동 버튼을 표시한다. facts는 분류 문구를 포함해 의견 모델에 전달하지만 원문 인용과 ID는 기존 opinionContext 허용 목록으로 제외한다. 사용자 facts 변경은 오래된 factEvidence를 지워 잘못된 근거 연결을 방지한다. 근거 연결 없는 과거 문서는 확인 경고와 함께 호환한다. document JSON 확장이며 새 DB 컬럼·원격 SQL·런타임 의존성은 없다. 기존 Adapter/DI를 유지하고 document-grounding.ts의 순수 함수로 검증 책임을 분리했다.

이 검증은 **인용 존재와 출처 연결 확인**이다. 발언의 진위·법률 현행 여부·요약의 의미적 타당성을 자동 보장하지 않는다. 외부 조사 기능을 추가하지 않았으며 관련 자료가 없으면 미확인으로 남긴다. 변경 후 생성되는 새 문서에 적용되고 과거 저장 문서를 자동 재생성하지 않는다.


### 문서 품질 검증에서 발견한 실패와 제한

위 주제3종의 유형 구분은 맞았지만 입력 대화가 없는 실험에서 Qwen이 확인되지 않은 법률 내용을 ‘확인됨’으로, 존재하지 않는 참여자의 주장을 사실 목록으로 생성했다. 따라서 이 실험은 문서 정확성 통과가 아니다. 관련 대화/이전 문서가 전혀 없는 경우에는 서버가 질문만 보존하고 요약·사실·쟁점을 ‘근거 없음/미확인’으로 제한하며 임의 논거를 제거하는 방어를 추가했다. 찬반 선택지도 중립적인 동의/반대/보류 기준으로 제한한다. 대화가 있는 경우까지 개별 사실과 출처를 자동 검증하는 구조는 미완료다. 이 점과 JEV의 오답 때문에 전반적 성능 개선 완료로 보고하지 않는다. 프론트 호스트 빌드는 통과했다.


### 실제 주제별 문서 검증 결과

학교 Qwen에서 ‘청년적금 월 지원액’→numeric, ‘민식이법은 악법인가’→stance, ‘현금 지급/교통 이용권’→choice를 각각 확인했다. 보고서는 Git 제외 `.tmp/gpu-ai/topic-kinds-report.json`. 법률 사실을 외부 검증한 실험이 아니라 질문별 문서 구조/응답 유형 검증이다. 수치 구간 라벨은 모델 문구의 이하/미만 오류를 방지하도록 서버가 경계값으로 생성한다.

중요한 한계: 술 정산 합성 사례의 상세 Qwen은60,000/3=20,000원을 답했으나 JEV0.6B는1만원 미만 구간을 선택했다(조건부 확률 약0.795). **구조 연결은 성공했지만 정답 품질 검증에는 실패했다.** 수치를 높이거나 정답처럼 숨기지 않는다. 단순 계산도 JEV가 틀릴 수 있으므로 프롬프트 개선만으로 품질이 해결됐다고 보고할 수 없다. 선택지 순서 대조·더 강한 모델 비교·객관식 계산 검증이 후속 과제다. 전체200명 품질 실험·최종 화면 시각 검증은 미실행이다. 원문 근거는 사실 확인용, 편집한 facts는 모델에 전달되지만 개별 사실별 source ID 연결과 품목별 전용 표 편집은 아직 없다.


## 주제별 판단 문서·응답 구현 · 2026-11-03

사용자 후속 실행 요청으로 계획의 구현에 착수했다. 문서는 질문 의도→관련 사실/주장/미확인 정보→쟁점→판단 기준→응답 유형과 선택지를 생성한다. `answerSchema`는 stance/numeric/choice이며 금액에 고정하지 않는다. facts와 응답 기준은 편집 가능하고 원문은 사실 확인용으로 제공한다. 원문 체크만으로 입력이 달라지는 것처럼 보이던 UI를 제거했다. 선택지는2~9개, 수치형은 연속 하한 포함/상한 제외 구간과 별도 보류 항목을 검증한다. Qwen은 상세 결론·수치(수치형만)·근거 특성, JEV v2는 같은 문서의 항목 ID·조건부 확률을 반환한다. JEV 구간을 정확한 금액으로 변환하지 않고 수치 평균은 상세 실제 응답만 사용한다.

공통 인터페이스/DI·HTTP Adapter를 유지하고 검증은 answer-schema.ts의 순수 함수로 분리했다. 과거 문서는 v1 찬반 호환 경로로 읽는다. 새 결과는 고정 동의도/신뢰도 스펙트럼을 주요 결과로 사용하지 않으며 이름 옆에 실제 수치/선택 결과를 표시한다. 연령대·성별·지역·학력 그래프는 바로 보이고 나머지7개는 개별 펼침 영역, 분석에 사용한 추가 조건은 기본 펼침이다. 기존20+180 예산과 AI 진행 표시를 유지한다. 새 런타임 의존성·파일 이동/삭제·커밋/푸시·DB 마이그레이션은 없다.

SSH 직접 접속(-F NUL)으로 기존 설치를 확인했고, 꺼져 있던 Qwen/JEV를 기존 캐시로 재기동했다. JEV 브리지를 v1/v2 호환으로 반영하고 로컬18080/18081 터널을 열었다. 상세 술 정산 합성 사례에서 금액형 문서·상세 답변·JEV 구간 응답을 확인했다. 실제 모델 실험은 소규모이며 품질 전반 개선이나200명 전체 성공을 뜻하지 않는다. 백엔드106개 테스트·JEV4개 테스트 및 프론트 타입/lint, 백엔드 빌드/lint 통과 기록이 있다. 최종 주제3종 분류 검증과 화면 시각 검증 상태는 별도 결과를 따른다.

| 결과 필터 | 저장된 최대 200개 응답을 다시 집계, AI 재호출 없음. 개별 답변은 상세 표본만 표시 |

표본이200명보다 적으면 상세20명에 우선 배정하고 나머지를 JEV에 배정한다. 예:70명 → 상세20+JEV50,13명 → 상세13+JEV0. 후자의 경우 JEV 연결 없이도 실행 가능하다. 표본 미리보기에는 AI 호출이 없다.

원본 NVIDIA 데이터에 소득이 없어 필터·응답 특성에서 제거했다. 이름은5만 본문 모두의 `이름 씨` 접두어에서 추출한다. 이전 저장 결과처럼 이름이 없으면 프론트의 고정 합성 이름을 호환용으로 사용한다. 새11종 특성이 없는 과거 결과의 재집계 값은 미상이다. 전공은4년제/대학원의 학사 전공, 현역 여부는 군필 구분이 아니며 주택 유형은 소득·점유 형태가 아니다. [실측 기준](../database/persona-filters.md)을 따른다.

데이터 조회는 `/conversations/:id/personas/{facets,preview,search,sample}`이다. [API 요청·응답](../backend/api.md)을 따른다. 선택지·목록·표본·검토 문서와 AI 실행의 책임을 분리했다. `PersonaSource` 인터페이스와 Supabase 어댑터/DI를 논쟁 모듈에서도 재사용한다. private SECURITY DEFINER는 UID/본인 대화를 명시적으로 검사하고 원본 테이블 권한을 외부에 주지 않는다. public wrapper는 INVOKER·authenticated 전용이다.

## 학교 서버 연결 순서

1. 기존 마이그레이션 뒤에 `20261102002606_persona_debates.sql`, `20261102004905_debate_documents.sql`, `20261102045839_persona_query_api.sql` 순서로 적용한다. 연결된 프로젝트에는 이미 적용했다. 원격 버전 대응은 [DB 기록](../database/schema.md)을 확인하고 같은 SQL을 재적용하지 않는다.
2. 기존 `SUPABASE_URL`·`SUPABASE_PUBLISHABLE_KEY`와 로그인을 사용한다. 페르소나 전용 관리자 키는 설정하지 않는다. 위4개 데이터 API는 학교 AI가 없어도 조회할 수 있다.
3. 기존 `SCHOOL_AI_BASE_URL`, `SCHOOL_AI_MODEL`, 필요한 경우 `SCHOOL_AI_API_KEY`를 설정한다. Qwen은 기존과 동일하게 `/tokenize` 및 OpenAI 호환 `/v1/chat/completions`를 제공해야 한다. URL의 `/v1` 중복에 유의한다.
4. `JEV_OPINIONS_URL`에 자체 서버의 **완전한 의견 요청 URL**, 필요한 경우 `JEV_OPINIONS_API_KEY`를 설정한다. 미설정이면 `JEV_NOT_CONFIGURED`; 임의 엔드포인트나 Qwen 대체 응답을 만들지 않는다.
5. 백엔드를 재시작하고 의견 탭에서 조건·발언자 선택 → 논쟁 입력 → 쟁점 문서 만들기 → 문서 수정/근거 선택 → 문서 확정·분석 시작을 수행한다. 개발 Compose는 위 세 변수를 백엔드에만 전달한다. 문서 생성에는 Qwen만 필요하며 JEV 미설정도 문서 검토까지는 가능하다.

입력 경로는 `/conversation/:conversationId/opinions`, 분석별 경로는 `/conversation/:conversationId/opinions/:analysisId`, 기록은 마지막 부분이 `history`다. 확정 후 문서는 해당 분석의 스냅샷으로 읽기 전용이며 새 논쟁은 새 기록으로 작성한다. 문서 속 발언자별 보기만 바꿔서는 포함 근거가 바뀌지 않는다. 체크 상태는 문서의 검토용 근거 선택이다. 의견 모델에는 원문·화자·근거 ID를 보내지 않으며, 반영할 내용은 핵심 요약·쟁점에 작성해야 한다.

JEV 실제 규격이 아래 제안과 다르면 `JevOpinionHttp`를 변경하거나 `JevOpinions` 인터페이스의 다른 어댑터로 교체한다. TypeSafe 외부 SDK는 사용하지 않는다. 현재 런타임 의존성 추가 없음.

## JEV 의견 요청·응답 계약

현재 JEV-CPU 브리지는 `opinion`에 `scoreKind:"conditional_option_probability"`와5개 `optionProbabilities`를 함께 반환한다. 강한반대/반대/중립/찬성/강한찬성 순서이며 승리 라벨과 좌표-1/-0.5/0/0.5/1을 검증한다. 이때 confidence는 승리 선택지 확률이고 opinion은 해당 라벨이다. 아래 선택적 메타데이터가 없는 과거 생성형 서버 응답과도 호환한다. 원본 프로젝트의 웹 UI API 대신 검토한 엔진을 호출하는 전용 브리지다.

`POST $JEV_OPINIONS_URL`, `Content-Type: application/json`. 키를 설정한 경우에만 `Authorization: Bearer $JEV_OPINIONS_API_KEY`. 요청별 90초 제한, 전체 작업 2시간, 백엔드당 최대 2개 작업. 자동 재시도는 하지 않는다.

```json
{
  "version": "persona-opinion-v1",
  "topic": {
    "question": "불가피한 지각에는 벌금을 면제해야 할까?",
    "proposition": "불가피한 사정에 의한 지각은 벌금을 면제해야 한다.",
    "context": "합성 논쟁의 맥락",
    "evidenceMessageIds": []
  },
  "persona": {
    "id": "00000000000000000000000000000001",
    "age": 30,
    "sex": "여자",
    "province": "서울",
    "education": "4년제 대학교",
    "occupation": "회사원",
    "name": "김가람",
    "maritalStatus": "미혼",
    "familyType": "혼자 거주",
    "district": "서울-강서구",
    "bachelorsField": "공학",
    "housingType": "아파트",
    "militaryStatus": "비현역",
    "ageGroup": "30-39",
    "persona": "합성 페르소나 요약"
  }
}
```

```json
{
  "version": "persona-opinion-v1",
  "personaId": "00000000000000000000000000000001",
  "model": "Meanblock/JEV-CPU@759fa606:Qwen3-0.6B@c1899de2",
  "opinion": {
    "agreement": 0.5,
    "confidence": 0.82,
    "opinion": "찬성",
    "scoreKind": "conditional_option_probability",
    "optionProbabilities": [0.03, 0.04, 0.06, 0.82, 0.05]
  }
}
```

agreement는 **proposition에 대한** -1~1 유한 숫자, confidence는0~1 유한 숫자, opinion은 비어 있지 않은500자 이하 문자열이다. ID·버전·모델을 검증한다. Qwen의 confidence는 자기평가, JEV-CPU는5개 선택지 중 승리 확률이며 둘 다 보정된 정확도가 아니다. 학교 서버도 논쟁·페르소나·대화 속 지시문을 데이터로 취급한다.

Qwen 상세 응답은 같은 opinion 구조에 `answer` 문자열을 추가한다. 논쟁 정리는 `question`(300자), `proposition`(300자), `context`(800자), `evidenceMessageIds`(최대20개), 선택적 `keyIssues`/`supportingLogic`/`opposingLogic`(각6개·500자)을 검증한다. 실제 프롬프트는 학교의 짧은 컨텍스트에 맞춰 질문/주장100자·맥락200자·논리각2개·근거6개 이하를 요청한다. 근거는 입력/이전 요약에 존재하는 ID만 허용한다. 문서의 statements(화자/발언)는 모델이 생성하지 않고 서버가 원문에서 연결한다.

## 통계 정의

| 항목 | 정의 |
| --- | --- |
| 원형 분포 | 강한 반대 [-1,-.6], 반대 (-.6,-.2), 중립 [-.2,.2], 찬성 (.2,.6), 강한 찬성 [.6,1]. 완료 응답 각각 동일 가중치 |
| JEV 가중 입장 | `Σ(agreement × confidence) / Σconfidence`, JEV 완료 응답만 사용 |
| 상세 응답 일치도 | `Σ[confidence_JEV × (1 - abs(agreement_detail - agreement_JEV)/2)] / Σconfidence_JEV` |
| 집계 불가 | JEV 완료 응답이 없거나 신뢰도 합0이면 가중 입장·일치도 null. 0%로 바꾸지 않음 |
| 인구 통계 | 각 범주의 선택 수·완료 수·다섯 입장 수. 소표본에 대해 대표성을 주장하지 않음 |

일치도는 **입장 좌표 거리**로 계산한 지표이며 상세 답변 문장의 의미를 JEV가 직접 판정한 값은 아니다. 문장별 의미적 동의 평가가 필요하면 별도 계약·모델 평가가 필요하다.

## 실패·실행 경계

개별 잘못된 JSON/수치/형식·컨텍스트 초과는 해당 응답만 실패로 남긴다. 전부 실패하면 `NO_VALID_RESPONSES`. 학교 서버 연결·인증 장애는 전체 작업을 실패시키며 만들어낸 응답으로 대체하지 않는다. 현재 학교 2,048토큰 설정에 긴 페르소나가 들어가지 않을 수 있다. 페르소나를 임의로 자르지 않고 `AI_CONTEXT_ERROR`로 표시하므로 실운영 전 모델 컨텍스트를 점검해야 한다.

긴 대화는 누적 요약이므로 모든 원문을 조사하더라도 앞 구간의 세부 논점이 요약 과정에서 누락될 수 있다. 최종 논쟁과 원문 근거를 확인해야 한다. 단일 백엔드 프로세스 실행을 가정하며 재시작된 미완료 작업은 조회 시 `JOB_INTERRUPTED`로 정리한다. 다른 인스턴스가 실행 중인 작업을 인식하는 분산 worker/lease·자동 재개는 미구현이다. 사용자 토큰은 소유자의 폴링 시 갱신되지만 장시간 화면을 닫아 토큰이 만료되면 DB 저장이 실패할 수 있다.

## 검증

후속 변경 검증: 백엔드67개 테스트·타입·양쪽 lint·프론트 타입·양쪽 빌드 및 임시 PostgreSQL의 두 마이그레이션 검증 통과. 문서 생성→review 대기, 페르소나 호출 없음, 실제 발언자 필터·근거 연결, 문서 수정·위조 근거 거절·revision 충돌·중복 시작·확정 문서 사용·기록 소유권·재집계를 확인했다. 기존62개 통과 기록은 아래 과거 작업 기록이다.

합성 브라우저 QA에서 가로 필터·전체/개별 선택, 문서 전용 URL 이동·질문 수정·발언자별 보기·근거 해제·v2 저장·확정·분석 결과·기록 다시 열기를 확인했다. UUID 표시를 제거하고 고정 합성 이름과 색상 입장 배지를 사용한다. 이전 QA에서는 UUID 해시 이름을 사용했으며 현재는 원본 본문의 이름을 우선한다. 390px에서 페이지 가로 넘침 없음·콘솔 오류0. 스크린샷은 `.tmp/debate-qa/{filters,document,responses}-v2.jpg`다. 원격·학교·Auth E2E는 미실행이다.

백엔드 Node 테스트 62개 통과(새 테스트21개 포함), 양쪽 타입·lint·프로덕션 빌드 통과. HTTP 테스트는 샌드박스 로컬 포트 EACCES, 프론트 빌드는 출력 폴더 EPERM 후 호스트 권한에서 같은 검증을 통과했다.

브라우저에서는 실제 기능 컴포넌트를 임시 번들로 로드하고 Auth/API 경계에만 합성 데이터를 연결해 검증했다. 500명 상세50/JEV450 분포·원형 차트·스펙트럼·지도 선택·125명(상세13/JEV112) 재집계·개별 응답10개 페이지 렌더링을 확인했다. 390px에서 페이지 가로 넘침 없음, 표 내부 스크롤 동작, 콘솔 오류0건. 실제 계정 로그인·DB 저장·학교 추론의 E2E 검증은 아니다. QA 스크린샷은 `.tmp/debate-qa/persona-debate-result.jpg`에 저장했다.

원격 MCP SQL 조회는 3회 모두 `Database is possibly not accessible at the moment`로 실패했다. 원격 DDL·실제 학교 모델 호출은 미실행이다. `.tmp/debate-qa`의 PGlite 임시 PostgreSQL 환경에서 기존 페르소나 스키마·대화 FK 선행 구조·신규 SQL을 실행하고 `supabase/tests/persona-debates.sql`의 표본/권한/RLS/연쇄 삭제 검증 및 롤백을 통과했다. 실제 Supabase Auth/PostgREST 전체 연동 검증을 대체하지 않는다. QA 도구는 Git 제외되며 앱 의존성을 변경하지 않는다.
