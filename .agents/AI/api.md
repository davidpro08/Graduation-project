# AI 연결 계약과 분석 HTTP 초안

## 모순 명제 파이프라인 · 2026-11-07

모순은 명제 추출/영속화 후 JEV claim-pair-v1으로 판단하며 일정은 기존 Qwen 경로다. 사용자 스키마·DB 캐시·세 분류·오류·배포 조건·검증은 [명제 계약](claims-plan.md)을 따른다. 아래 모든 구간을 Qwen으로 직접 모순 분석한다는 기록은 이전 구현이다.

## 최종 마크다운 입력 계약 · 2026-11-03

새 문서의 markdown을 사용자가 편집·저장·확정하면 opinionContext가 {question,proposition,context,documentFormat:'markdown',answerSchema,evidenceMessageIds:[]}로 제한한다. context는 확정 문서 문자열과 정확히 같으며 중복 정제에도 보존된다. 실제 Qwen/JEV 요청의 question은 context 문서 안의 질문을 따르도록 지정한다. 원래 제목·facts·검색 요약·대화 원문을 추가 판단 근거로 다시 보내지 않는다. 기존 answerSchema가 응답 수집 형식이다. 최종 문서의 사실/조건 판단과 선택지 분류를 구분한다.

Qwen은 기존 JSON 응답 형식과 입력 토큰 검사를 유지하고 JEV는 v1/v2 HTTP 계약을 유지한다. 기존 학교 브리지는 topic 전체를 state로 받으므로 context 문서를 전달할 수 있다. 학교 서버 코드·모델·프로세스는 이번 작업에서 교체하지 않았다. 문서 최대10,000자가 항상 모델 컨텍스트에 들어간다는 보장은 없으며 임의 절단하지 않는다. 신규 마크다운이 없는 과거 입력은 항목별 호환 경로를 유지한다.

자료 정리는 선택한 발췌 ID를 원문에 연결하는 방식이며 자유로운 모델 설명을 새 facts로 확정하지 않는다. [조사·편집·재조사·확정 상세](persona-debates.md#최종-마크다운-중심-조사분석-파이프라인--2026-11-03), [API](../backend/api.md#최종-문서-조합재조사-api--2026-11-03)를 따른다.

## 모니터링 진단·실패 다시시작 · 2026-11-03

사용자 GPU 그래프에 대응해 읽기 전용으로 실제 작업 상태와 학교 로그를 확인했다. 2026-11-03 11:20:07 KST 시작 작업은11:21:09에 AI_REQUEST_TIMEOUT(약62초,0명)으로 실패했다. 직전 작업은JOB_INTERRUPTED였다. 학교 Qwen/JEV tmux는 살아 있고 GPU0%/VRAM23119MiB, 최신 로그의 Running=0/Waiting=0으로 유휴였다. OOM/학교 프로세스 종료의 증거는 없었다. 요청별 HTTP200은 내용 검증 성공을 뜻하지 않으며 첫 응답 뒤 재시도 중60초 전체 제한에 걸린 정황이다. 첫 응답의 세부 검증 실패 코드는 과거 로그가 없어 단정하지 않는다.

초안 출력1536→1152토큰, 짧은 항목/인용 지시로 줄이고 문서 모델 단계의 전체60→100초 한도를 조정했다. 실제20~21토큰/초 로그에 비해 기존60초 예산이 재시도를 수용하기 어려웠다. 추가 재귀 호출/전체 대화 조사는 도입하지 않았다. 이후 진단을 위해 원문·키를 제외한 시도 번호/오류 코드만 Logger에 기록한다. 실제 모델 재요청·서버 재기동은 수행하지 않았다.

POST /api/persona-debates/:id/restart {mode:'document'|'opinions'} →202. 본인 failed 작업만 허용하며 원래 실패 기록은 보존한다. 입력·필터·발언자를 복사한 새 UUID/새 표본 작업을 만든다. document는 빠른 문서 생성 후review에서 멈추고, opinions는 저장된 문서 스냅샷을 복사해 의견을 새로 요청한다(이전 부분 응답 이어받기는 아님). 문서 없음400·잘못된 모드400·타인404·실패 이외409·활성 작업 제한과 DB 중복 방지를 유지한다. 기존 인터페이스/DI·저장소 Adapter를 재사용해 DB 마이그레이션·권한 변경은 없다.

실패 카드에 문서 생성 다시시작 또는 AI 의견 요청 다시시작을 제공하고 문서가 있으면 문서부터 다시 만들기도 옆에 표시한다. 접수 중 비활성화·진행 표시·오류 안내·새 분석 페이지 이동을 연결했다. 자동 재요청하지 않고 사용자의 버튼 클릭으로만 실행한다.


## 빠른 검색 초안으로 전환 · 2026-11-03

사용자 정정으로 전체 대화 페이지 순회·구간별 누적 요약·재귀 분할을 문서 생성에서 제거했다. 기존 messages search API로 질문에서 추출한 최대6개 핵심 단어를 첫40개씩 제한 조회한다(동시3개). 단일 발언자는 DB 조건에도 적용하고 복수 발언자는 후보에서 제한한다. 중복·무관·제외 화자를 제거하고 관련도순 최대16개/약6KB의 단어 주변 발췌만 한 번에 Qwen에 보낸다. 조회한 후보가 없으면 대화 없이 질문만 정리한다. 전체 데이터에서 일치가 전혀 없음을 보장하는 검색은 아니며 first-page 제한과 복수 화자 희소 조건으로 관련 발언을 놓칠 수 있다. 결과에 검색어·후보 수·참고 수·부분 조사 경고를 표시한다.

AI 호출은 기본1회, 실패 시 입력을 줄여 최대1회 재시도하며 previous=null이다. 재귀 분할·누적/전체 요약은 없다. 모델 단계는60초 대기 제한, 출력1536토큰·짧은 초안 지시를 사용한다. DB 검색 시간은 별도이며 완료 시간을 보장하지 않는다. JEV 관련성 호출은 추가하지 않아 대기 경로를 늘리지 않는다. 기존 인용 검증·주제별 응답 기준·원문 제외 의견 입력은 유지한다. sourceCoverage JSON에 mode=keyword/keywords/matchedMessages/searchFailed를 추가하며 신규 DB 마이그레이션은 없다. 순수 검색/발췌 함수를 document-search.ts로 분리하고 기존 Adapter/DI를 유지했다.

이전의 ‘모든 페이지 조사/구간별 복구’ 문서 기록은 과거 동작이다. 사용자 직접 시험을 위해 실제 AI 요청·학교 서버 변경은 하지 않았다. 새 문서 생성 요청부터 적용한다.


## 문서 근거 품질 보완 · 2026-11-03

사용자 요청으로 문서 품질만 보완했다. **실제 학교 AI 요청·모델 실험·서버 재시작은 실행하지 않고 사용자 직접 시험을 기다린다.** 프롬프트는 질문 의도·사실/참여자 의견/가정/미확인 정보·쟁점·판단 기준을 분리하고 없는 반대 논거나 합의를 채우지 않도록 강화했다. optional factEvidence(최대8개: text/kind/messageId/quote)를 생성하며 reported/opinion의 인용은 실제 현재 구간에 포함되거나 이전 구간에서 확인한 동일 항목이어야 한다. 위조 ID/인용·이전 사실 변형은 AI_TOPIC_EVIDENCE로 거절하고 기존 재시도/분할 정책을 따른다. 가정·미확인 항목에는 원문 근거를 붙이지 않는다.

화면은 항목별 분류·원문 인용·근거 이동 버튼을 표시한다. facts는 분류 문구를 포함해 의견 모델에 전달하지만 원문 인용과 ID는 기존 opinionContext 허용 목록으로 제외한다. 사용자 facts 변경은 오래된 factEvidence를 지워 잘못된 근거 연결을 방지한다. 근거 연결 없는 과거 문서는 확인 경고와 함께 호환한다. document JSON 확장이며 새 DB 컬럼·원격 SQL·런타임 의존성은 없다. 기존 Adapter/DI를 유지하고 document-grounding.ts의 순수 함수로 검증 책임을 분리했다.

이 검증은 **인용 존재와 출처 연결 확인**이다. 발언의 진위·법률 현행 여부·요약의 의미적 타당성을 자동 보장하지 않는다. 외부 조사 기능을 추가하지 않았으며 관련 자료가 없으면 미확인으로 남긴다. 변경 후 생성되는 새 문서에 적용되고 과거 저장 문서를 자동 재생성하지 않는다.


## 주제별 판단 문서·응답 구현 · 2026-11-03

사용자 후속 실행 요청으로 계획의 구현에 착수했다. 문서는 질문 의도→관련 사실/주장/미확인 정보→쟁점→판단 기준→응답 유형과 선택지를 생성한다. `answerSchema`는 stance/numeric/choice이며 금액에 고정하지 않는다. facts와 응답 기준은 편집 가능하고 원문은 사실 확인용으로 제공한다. 원문 체크만으로 입력이 달라지는 것처럼 보이던 UI를 제거했다. 선택지는2~9개, 수치형은 연속 하한 포함/상한 제외 구간과 별도 보류 항목을 검증한다. Qwen은 상세 결론·수치(수치형만)·근거 특성, JEV v2는 같은 문서의 항목 ID·조건부 확률을 반환한다. JEV 구간을 정확한 금액으로 변환하지 않고 수치 평균은 상세 실제 응답만 사용한다.

공통 인터페이스/DI·HTTP Adapter를 유지하고 검증은 answer-schema.ts의 순수 함수로 분리했다. 과거 문서는 v1 찬반 호환 경로로 읽는다. 새 결과는 고정 동의도/신뢰도 스펙트럼을 주요 결과로 사용하지 않으며 이름 옆에 실제 수치/선택 결과를 표시한다. 연령대·성별·지역·학력 그래프는 바로 보이고 나머지7개는 개별 펼침 영역, 분석에 사용한 추가 조건은 기본 펼침이다. 기존20+180 예산과 AI 진행 표시를 유지한다. 새 런타임 의존성·파일 이동/삭제·커밋/푸시·DB 마이그레이션은 없다.

SSH 직접 접속(-F NUL)으로 기존 설치를 확인했고, 꺼져 있던 Qwen/JEV를 기존 캐시로 재기동했다. JEV 브리지를 v1/v2 호환으로 반영하고 로컬18080/18081 터널을 열었다. 상세 술 정산 합성 사례에서 금액형 문서·상세 답변·JEV 구간 응답을 확인했다. 실제 모델 실험은 소규모이며 품질 전반 개선이나200명 전체 성공을 뜻하지 않는다. 백엔드106개 테스트·JEV4개 테스트 및 프론트 타입/lint, 백엔드 빌드/lint 통과 기록이 있다. 최종 주제3종 분류 검증과 화면 시각 검증 상태는 별도 결과를 따른다.


## 현재 페르소나 요약·의견 계약 · 2026-11-03

상세20/JEV180·최대200명으로 변경했다. Qwen refine는 summary(응답 최대2000자·프롬프트500자 이하), 기존 쟁점·논리·근거를 검증한다. 날짜/시간 구간·짧은 ID 별칭을 쓰며 문서 실패도 제한적 재시도/재분할한다. AI_TOPIC_STRUCTURE/AI_TOPIC_LENGTH/AI_TOPIC_EVIDENCE로 원인을 구분하고, 연결 대기와429는 AI_REQUEST_TIMEOUT/AI_BUSY 및 JEV_REQUEST_TIMEOUT/JEV_BUSY다. 상세와JEV 의견의 topic은 summary·question·proposition·context·논리만 허용하고 evidenceMessageIds는 빈 배열이며 statements/원문/화자는 제외한다. `sourceCoverage`와 warnings는 사용자 검토용 문서 metadata다. [제한·부분 실패·검증](persona-debates.md#현재-구성--2026-11-03)을 우선한다. 아래 변경하지 않았다는 문구는 이전 작업 범위다.

2026-11-02 모순 응답 title·summary, 일정 date/time/uncertain·근거 기반 suggestion, 날짜/30분 세션·짧은 근거 별칭, 구간 재시도·재분할·partial 결과와 AI_REQUEST_TIMEOUT/AI_BUSY 구분을 추가했다. 신규 완료 metadata·구체적 제한·이전 결과 호환은 [최신 분석 계약](analysis-flow.md#후보-표현대화-흐름오류-복구--2026-11-02)을 우선한다. JEV 및 페르소나 분석 계약은 변경하지 않았다.

2026-11-02 모순·일정의 모델 입력은 대화 마지막 날짜 기준 최근 한 달의 text만 대상으로 한다. DB 조회부터 날짜를 제한하며 토큰 검사·분할·근거 ID 검증은 유지한다. 실제 기간·텍스트 수는 완료 metadata.inputRange에 기록한다. [최신 규칙](analysis-flow.md#최근-한-달-분석--2026-11-02)을 우선한다. 페르소나 문서 조사 범위는 변경하지 않는다.

## 페르소나 의견 추가 · 2026-11-02

현재 학교 서버에 Meanblock/JEV-CPU를 설치하고 자체 브리지 `POST /v1/persona-opinion`을 연결했다. 저자의 원본 웹 서버 `/api/decide`를 그대로 공개한 것이 아니다. 반환의 `opinion.scoreKind=conditional_option_probability`와5개 `optionProbabilities`는 합1·범위·최대값/좌표/라벨 일치 검증 후 보존한다. JEV `confidence`는 승리 선택지 확률이며 Qwen의 자기평가와 구분한다. [실행·실험](gpu-experiments.md)을 우선하고 아래 이전 학교 미연결 기록은 과거 상태로 본다.

논쟁 정리·상세 의견에는 기존 학교 Qwen의 tokenize/chat completions 어댑터를 추가했고 간단 의견용 학교 JEV HTTP 어댑터는 제안 계약으로 구현했다. [요청·응답·연결 순서·통계 정의](persona-debates.md)를 따른다. 실제 학교 규격과의 연결은 사용자 후속 작업이며 모순·일정의 사전 판단 제거와 별개다. 아래 `/analyze` 초안과 이전 미구현 persona 출력은 이번 구현의 계약이 아니다.

현재 NestJS는 학교 Qwen 서버의 `/tokenize`와 `/v1/chat/completions`를 호출한다. 상세는 [분석 흐름](analysis-flow.md)을 따른다. PR #5 논의에 따라 TypeSafe JEV 호출과 SDK를 제거했다. 향후 jev-cpu는 자체 AI 서버가 맡을 예정이나 서버 구현, 엔드포인트, 인증 및 응답 계약은 미확정·미연결이다. 현재 사전 판단 없이 모든 구간을 분석한다.

| POST | `/analyze` | 한 작업의 분석 입력을 받아 결과 반환 | 서버 간 인증 필요; 방식은 연결 시 확정 | 미구현 |
| GET | `/health` | 프로세스 준비 상태 확인 | 노출 범위는 배포 시 제한 | 미구현 |

브라우저는 이 API를 직접 호출하지 않는다. NestJS는 사용자에게 작업 ID를 먼저 반환한 뒤 AI HTTP 호출을 실행한다. AI 응답의 비동기 콜백이나 SQS는 초기 계약에 포함하지 않는다.

## 입력 예시

합성 대화 예시이며 ID·시간은 설명용이다.

```json
{
  "jobId": "job-example",
  "analysisType": "contradiction",
  "conversationId": "conversation-example",
  "messages": [
    {"messageId": "m1", "speaker": "참여자A", "sentAt": "2026-09-29T09:00:00+09:00", "text": "제가 금요일까지 제출할게요."},
    {"messageId": "m2", "speaker": "참여자A", "sentAt": "2026-09-30T09:00:00+09:00", "text": "제가 제출하기로 한 적은 없어요."}
  ]
}
```

| 필드 | 의미 |
| --- | --- |
| jobId | NestJS가 발급한 작업 ID; 응답과 일치해야 함 |
| analysisType | `contradiction`, `persona`, `schedule` 중 하나 |
| conversationId | 분석 대상 대화 식별자 |
| messages | 메시지 ID·발화자·시각·본문; 실제 계정 ID나 비밀 키는 보내지 않음 |

## 출력 예시

```json
{
  "jobId": "job-example",
  "analysisType": "contradiction",
  "modelId": "mock",
  "result": {
    "items": [
      {"summary": "제출 약속 여부에 불일치 가능성이 있습니다.", "evidenceMessageIds": ["m1", "m2"]}
    ]
  }
}
```

공통 출력은 `jobId`, `analysisType`, `modelId`, `result`다. `modelId`는 실제 모델 식별 정보 또는 `mock`으로 기록한다. 결과 종류별 최소 항목은 다음과 같다.

| 종류 | result 초안 | 처리 |
| --- | --- | --- |
| contradiction | `items`: summary, evidenceMessageIds | 불일치 후보와 근거 표시 |
| persona | `opinions`: perspective, opinion, suggestion, evidenceMessageIds | 생성 관점·해결 제안 표시; 여론 비율 제외 |
| schedule | `candidates`: title, dateTimeText, evidenceMessageIds | 원문 날짜·시간 후보 보존; 사용자 확인 전 확정 일정으로 저장하지 않음 |

## 검증·오류

- jobId·analysisType이 요청과 일치하고 JSON 형태·결과 종류가 계약을 따라야 한다.
- evidenceMessageIds는 입력 메시지에 존재해야 한다. 후보가 없으면 빈 배열을 반환하며 근거를 만들어내지 않는다.
- NestJS가 HTTP 성공 여부와 별도로 결과를 검증한다. 잘못된 결과는 완료로 저장하지 않는다.
- AI 오류·타임아웃은 작업을 `failed`로 만든다. 재요청은 새 작업 ID로 처리하며 초기에는 자동 재시도를 전제하지 않는다.
- 상세 JSON 스키마, 본문·컨텍스트 제한, 시간 제한, 인증 헤더, 오류 응답 형식은 실제 연결 구현 전에 확정하고 문서화한다.

## 일정 제안 보강 · 2026-10-03

Qwen의 원문 날짜 표현·근거 ID 계약은 유지한다. 백엔드 후보 조회에서 해당 근거의 발언 날짜·시각으로 상대 날짜와 시간 범위를 결정하여 suggestion을 추가한다. 모호한 오전·오후는 확인 경고를 붙이고 사용자 확정이 필요하다. 상세 규칙은 analysis-flow.md의 일정 날짜·시간 제안을 따른다.
