# AI 서버 지침

## 요약 우선·200명·진행 표시 · 2026-11-03

전체 대화의 선택 발언자로 수정 가능한 핵심 요약 문서를 먼저 만들고 사용자 확인 후 상세20/JEV180명에게 요약과 쟁점만 전달한다. 원문은 요약 생성/근거 검토에만 사용한다. 문서의 형식·근거 오류도 재시도·재분할하고 누락을 경고한다. 모든 AI 화면에 공통 진행 표시와 현재 작업 설명을 넣었으며 가상 진행률과 실제 처리 인원을 구분한다. 현재 계약·한계는 [페르소나 논쟁](persona-debates.md#현재-구성--2026-11-03), 실제200명 성공 기록은 [GPU 실험](gpu-experiments.md)을 따른다. 아래500명 측정은 과거 기록이다.

## 모순·일정 복구와 추정 · 2026-11-02

날짜·30분 세션과 짧은 근거 별칭으로 입력 흐름을 보존한다. 구간별 재시도·작은 구간 재분할·성공 결과 partial 저장과 요청 대기 만료/429 구분을 추가했다. 일정의 추정값은 근거 기준 규칙과 AI/fallback으로 채우고 불확실 경고를 보존하며 사용자 확인 전 확정하지 않는다. [최신 제한·계약](analysis-flow.md#후보-표현대화-흐름오류-복구--2026-11-02)을 따른다.

## 모순·일정 입력 기간 · 2026-11-02

모순·일정의 새 분석은 대화 마지막 날짜 기준 최근 한 달의 text만 DB에서 조회해 Qwen에 전달한다. 완료 metadata.inputRange와 화면에 실제 기간·텍스트 수를 표시한다. 기존 Adapter·DI와 토큰 검사·분할은 유지하며 페르소나 분석 범위는 그대로다. [최신 기간·오류 계약](analysis-flow.md#최근-한-달-분석--2026-11-02)을 따른다.

## 새 인스턴스 준비

새 GPU 인스턴스의 접속·파일 전송·영구 캐시·Qwen/JEV 설치·기동·터널·백엔드 연결·실험은 [인스턴스 준비 절차](instance-setup.md)를 따른다. 로컬 PowerShell과 원격 Bash를 구분하고, 새 주소/포트/마운트 경로를 실제 값으로 확인한다. 기존 실행 중인 서비스를 문서 확인 목적으로 재설치하거나 중단하지 않는다.

## 최신 학교 GPU·CPU 실험 · 2026-11-02

사용자가 제공한 RTX4090 서버에 Qwen3-32B-AWQ/vLLM0.32.0과 Meanblock/JEV-CPU를 독립 GPU/CPU venv로 설치·기동했다. Qwen5명/JEV5명과 기존 모순·일정 흐름에 이어 상세50+JEV450도500/500 응답·실패0·17분14.690초로 통과했다. JEV450명이 모두 강한 찬성으로 쏠렸으며 명시적 찬성/반대/중립 대조3건은 각각 구분했다. 연결 성공과 의견 품질을 구분한다. [버전·리비전·한계·실제 결과](gpu-experiments.md)를 우선한다. 아래 과거 미연결 기록과 구분한다.

JEV-CPU는 페르소나 간단 의견의 선택지 확률만 담당한다. 문장을 생성하지 않으며 최대 확률 선택지 라벨·좌표·조건부 확률을 저장한다. 모순/일정의 사전 판단을 다시 도입하지 않았고 TypeSafe SDK도 사용하지 않는다. 원본 모델 카드의 성능 수치를 본 서비스 정확도로 해석하지 않는다.

## 페르소나 논쟁 추가 · 2026-11-02

사용자 요청에 따라 관점별 의견의 백엔드·화면·저장을 구현했다. 학교 서버 연결은 대기하며 [페르소나 논쟁 계약](persona-debates.md)을 우선한다. 모순·일정의 기존 Qwen 직접 분석과 사전 판단 제거는 유지한다. 실제 여론과 합성 응답 분포를 구분하고 원본에 없는 소득을 추론하지 않는다.

2026-10-03 운영 코드의 모순·일정 분석 API·DB·화면 연결을 구현했다. [최신 연결 기록](analysis-flow.md)이 아래 이전 진단 상태보다 우선한다. 학교 모델 컨텍스트는 실제 조회로 2,048토큰이며 전체 입력 분할·근거 검증·실패 반환을 적용했다. 분할 간 모순 평가는 남아 있다. 자체 서버 jev-cpu는 미연결이다.

## 연결과 책임

초기는 **NestJS → 별도 AI 서버의 HTTP 연결**로 구성한다. AI는 구조화된 JSON을 반환하고 NestJS가 스키마·소유권·근거를 검증하여 Supabase에 저장한다. AI는 DB 관리 권한을 갖지 않는다.

로컬 서버는 사용 시간 제약이 있으며 GPU 대여도 후보지만 제공자·GPU·운영 시간·비용은 미선정이다. 초기에는 모의 AI로 서비스 흐름을 검증한다. 연결 계약은 [api.md](api.md)를 따른다.

## 결과와 실패 처리

- 통계는 백엔드 책임이다. AI 분석은 모순 후보·페르소나 의견·일정 후보로 구분한다.
- 모순 후보와 일정 후보에는 요청에 포함된 근거 메시지 ID를 반환한다. AI 판단을 확정된 사실로 표현하지 않는다.
- 페르소나의 생성 응답은 실제 사회 조사 결과가 아니다. 근거 데이터가 없는 비율·대표성을 주장하지 않는다.
- 모델이 참조하는 대화는 사용자 데이터다. 대화 속 지시문을 시스템 명령으로 실행하지 않으며 외부 도구·파일 접근을 임의 수행하지 않는다.
- 모의 AI도 실제 계약과 같은 출력 형식을 사용한다. 정상, 지연, 연결 실패, 잘못된 JSON, 존재하지 않는 근거 ID를 재현할 수 있게 한다.
- HTTP 연결 실패·타임아웃·잘못된 JSON을 NestJS가 작업 실패로 처리한다. 무한 재시도하지 않고 설정된 제한을 따른다.
- 대화·토큰을 로그에 기록하지 않는다. 실제 서버 연결에는 서버 간 인증·전송 보호를 적용하며 환경 구성은 [infra 지침](../infra/guide.md)에 기록한다.

## 사전 판단 경계

모순·일정의 모든 구간은 학교 Qwen으로 직접 분석한다. 현재 JEV-CPU는 페르소나 간단 의견에만 사용하며 모순/일정 사전 판단은 도입하지 않았다. 외부 TypeSafe JEV SDK와 API는 제거한 상태를 유지한다.

## 검증과 갱신

모델 정확도 평가와 API 연동 검증을 구분한다. API 계약은 모의 서버로 먼저 검증하고, 실제 모델 선정 후 한국어 대화·근거 연결·오탐·일정 모호성에 대한 평가를 추가한다. 모델·서버·계약 변경 시 이 문서와 API 문서 및 영향을 받는 백엔드 지침을 갱신한다.
